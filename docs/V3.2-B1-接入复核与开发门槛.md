## 追加迁移与批次边界

从 V034 追加 V035，B1 拟定 7 个实体：integration_connections、integration_mappings、integration_stock_movements、integration_stock_acknowledgements、integration_inventory_events、integration_stock_previews、integration_stock_applications。另按 2026-10-25 最终复核追加 V036 旧责任接管守护；后续 V037/B2 对应 integration_deliveries、integration_delivery_attempts、integration_delivery_receipts；V038/B3 对应 integration_shipment_events、integration_shipment_applications、integration_responsibility_reviews。这是仓库内部开发安排，不是实际供应商表结构；若后续复核需要拆分迁移，先在最新计划登记原因，不改已执行迁移。

B1 不开放商品订单外发、外部发货写入或取消结果。只接 A 草案的 B1 连接/映射/库存读取、预览、应用；仅在实现和真实响应验证后将对应操作并入运行契约及 TS/Dart，保留 A 草案标记和旧契约。客户端不允许指定库存目标/外部成功/水位，不引入 URL 代理或实际凭证配置。

## 库存日志接入

- 在既有 inventory_sale_events、inventory_adjustments、inventory_restock_events 成功写入同事务追加本地物理库存增量，源类型/源 ID 唯一，offer 内 sequence 连续。现有余额行锁保持原入口顺序；日志追加不得反向锁连接/映射，避免与集成应用形成死锁。
- 商品收款扣减、商家手工调整、付款后取消返库、售后接收返库逐一接入；退款成功本身不增加库存。预占只使版本变化，外部应用单独记来源，不重复当作本地待导出增量。
- V034 老数据不补造外部事件、映射、确认或发货；既有历史事实保留。新映射从明确 epoch、零现有和零预占、无旧未结订单/责任的专用合成范围开始。既有非零库存接管另有规则前拒绝。
- 同事务校验 source 前后库存、结果版本和 journal 摘要；漏写/重复/异载/跳号必须检测。采集与预览都要覆盖原商品原路径，不能只对新测试路由写日志。

## 连接、应用与权限

连接初建暂停，作用域必须匹配 merchant/store/offer。只有服务器受保护夹具可生成 TEST_SCENARIO 外部事件和确认事实；不能让浏览器创建“已同步”的水位。新建映射和退役须与并发声明串行，同一外部键/offer 唯一活动来源，退役保留历史。二次验证、权限撤销、跨门店和账号切换都要验证。

预览包含服务端真实库存/预占版本、映射/连接版本、事件/外部版本/前缀摘要、最新本地序列和本人五分钟快照。不可计算目标为 null；应用只接受 preview ID 和已阅摘要，并在锁下重算，再同事务写库存、应用、审计/Outbox。重复同键只回原结果，不重复加库存；审计失败整体回滚。生产/缺开关/非模拟供应器默认拒绝，暂停不释放旧未知责任。

## 原入口时序复核备注

OfferService.adjust 先在余额锁下写 inventory_adjustments，随后更新余额；PaymentService 商品确认与 CancellationService/AfterSaleService 返库则先改余额再写对应事实。B1 的统一日志不能假定所有来源都采用相同先后顺序：来源触发器只从不可变事实推导值并在现有余额锁下追加序列；需要与最终余额对应的完整性检查使用事务结束时的延迟约束。

本地序列按 offer 串行，仅销售/调整/返库是待外发增量；外部库存应用保存独立物理变化/版本依据，不再次放入待外发增量。核验余额链时需同时考虑应用记录，不能把上一次本地业务变动后的余额误当作下一次变动前余额而忽略期间的外部应用。来源唯一键应包含源类型和源事实 ID；留存 before/resulting/库存版本以供逐项对账。

日志触发器不能在持有 offer/余额后再锁连接或映射；连接/映射退役也不能在其锁下反向获取所有订单。涉及订单的路径仍先取原订单锁链，随后取集成范围锁；批量稳定排序，用实际并发测试证明。新的只读来源投影不得凭新建映射补造过去的库存或外部确认。

新表的不可变/禁止 TRUNCATE 保护、现有四处测试库清理清单、迁移数量与实际隐私元数据同步处理；仅测试夹具可临时关闭相应清理保护，生产约束保留。A 基线的 7 份历史生成 bundle 与 canonical 源输入保持区分，后续 B1 业务变更必须有独立新基线/实际运行门禁，不能静默删除保护。
