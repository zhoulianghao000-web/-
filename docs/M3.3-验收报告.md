## 基线和交付

M3.2 PR #4 经复核最终五个 CI Job 全部成功后，按用户授权合并，合并提交 `4d890d48f5170b8c8f33fc167a43e59d624ba622`。本批 `codex/pawday-m3.3` 从该主分支创建，实现提交 `cfb2b9d3ccfca78627a97979c7588dab2ceebda1`。

交付门店/默认履约范围报价、价格和履约修改、上架/暂停，管理员冻结/解冻/下架，商户统一幂等库存 Adjustment、不可覆盖流水及两端页面；生成 TypeScript/Dart 客户端，更新运行时机器契约与 CI。详细模型和操作协议见仓库 `docs/M3.3-商家报价与库存.md`。

新 Offer 是 DRAFT、库存为零。SKU/品牌/SPU 有效且存在已发布标准资料才能创建或上架。整数分定价，会员价可空且不高于普通价；PATCH 仅接受价格/履约，不接收库存、身份、状态或配料。报价与库存各自维护版本。最多 50 项的批量报价变更同事务，任意错误全部回滚。

merchant_id/actor 从会话取得，门店归属由复合外键和当前员工 scope 双重约束。跨商户及同商户未授权门店返回 404；授权撤销后，读取、变更及幂等重放都被拒绝。默认履约范围必须显式 `offer.default-scope` 授权。非下架报价在 merchant+SKU+store 内唯一，NULL 默认范围参与唯一约束。下架保留原记录、库存和历史，允许重新建立新报价。

库存调整只接受非零 delta、reason_code 和 expected_version。余额保证 on_hand>=reserved>=0，可用数量由数据库派生；扣减侵占预占返回冲突，不覆盖库存。幂等键在同一商户跨员工统一去重，变更 payload 被拒绝。流水、余额、审计与 Outbox 同事务；审计或事件失败回滚全部并可重试。UPDATE/DELETE/TRUNCATE 都不能更改库存调整流水。

管理员风控需要 ADMIN realm/RBAC、当前 session/action 绑定的一次性 reverify 和审计；冻结时商家不能改价或改变状态。解冻恢复 PAUSED，不自动恢复销售；商家随后明确上架。冻结期间仍能登记实物盘点，DELISTED 不接受新的商家变更。

事件 `OfferStateChanged`/`InventoryAdjusted` 在事实事务中写 Outbox，broker confirm 后留存在持久 quorum 队列 `pawday.offer.facts`，无 TTL、暂不消费。它们是 M3.4 的输入事实，不能直接冒充要求 sku_id/revision 的旧搜索投影事件。搜索不可用不参与报价事务。
