# M6.8 搜索与求购实现约束

日期：2026-10-12。用户确认：运营通知留白，完成筛选排序和无结果求购。

## 搜索

冻结的 OpenSearch v1 投影缺少商品名称、包装及评价字段。本批保留既有索引版本/alias/Outbox 重建与故障门槛，由真实 OpenSearch 分批发现 SKU 身份；PostgreSQL 在同一只读 repeatable-read 事务中读取现行已发布标准、有效商家报价、库存、已支付净销量和公开审核评价，完成全部关键词与组合筛选、排序，然后分页。不是先索引分页再过滤，也不把搜索派生数据当交易事实。

该方案面向当前小规模模拟目录。候选身份默认上限10,000（含墓碑，受控配置范围100–50,000）；超过返回503 SEARCH_CANDIDATE_LIMIT，不静默截断。每批500，SQL筛选后只水合当前页。未进行生产容量验收；后续大规模目录需索引v2、过滤下推及专项压测，不能把本批当作该项已完成。

支持宠物类别、品牌、价格区间（整数分）、现行规则年龄阶段、粮食类型、包装克数/单位、排除过敏原、库存。过敏原信息未知的商品不能通过排除筛选。库存和最低报价由同一有效Offer集合计算；只看有货时去除无货报价。无货查询指有效报价全部无可用库存。商品价不含运费或优惠。

综合排序依次采用关键词关联、公开商品评价/服务评分、已支付净销量、价格；另有价格升降、销量和好评排序。销量只计算成功支付项并减已退款单位；付款后取消和退款单位是同一事实，不能重复扣减。评价只采用PUBLIC已发布版本。不存在的质量/适配分不补造，不借AI扩大筛选。

最终UUID稳定裁决同分。加密游标绑定规范条件、完整排序摘要、偏移和5分钟期限；篡改/过期/跨条件400，当前事实使排序摘要变化409 SEARCH_RESULTS_CHANGED，用户重新查询。索引不可用503，商品数据库写入不依赖搜索成功，沿用Outbox补偿。

## 求购

消费者从无结果页面发起，保存标题、可选说明及规范筛选上下文；本人可查看/撤回，管理员集中处理，不广播商家，不产生采购、订单、扣款、到货或价格承诺，不增加运营通知。自由内容与答复加密，审计只记ID/状态，幂等回执不存明文内容。

状态OPEN→REVIEWING→RESOLVED/REJECTED；OPEN亦可直接完成或拒绝。消费者仅在OPEN/REVIEWING撤回为CANCELLED。终态不继续流转。每次变更追加不可覆盖历史，版本冲突拒绝。创建按用户事务锁去重相同未结束内容，滚动24小时最多20条新需求，重复请求与幂等重试不额外占额。

管理员需purchase-request.read/manage，处理密码二次验证、乐观版本、幂等和审计同事务；越权404/403，不向商家开放。留存政策、注销和生产依据继续PENDING；本批只同步152表/1217字段的结构盘点，不授权删除或填期限。
