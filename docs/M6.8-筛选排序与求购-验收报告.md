# M6.8 筛选排序与求购验收报告

日期：2026-10-13。结论：**本批筛选排序与无结果求购工程验收通过**，最终安装哈希见交付验证JSON；V1整体功能验收仍开放，生产BLOCKED，M6生产总验收未关闭。运营通知按用户要求留白。

## 实现

- 搜索：分页前执行商品名/品牌/SKU关键词匹配，组合宠物类别、品牌、年龄阶段、粮食类型、商品价格、包装规格/单位、库存和排除过敏原；支持综合、价格升/降、净销量、公开好评五类排序。价格以满足库存条件的有效报价计算，单位为整数分；过敏原未知时不通过排除筛选，条件不自动放宽。
- 一致性：条件绑定加密游标，同时校验结果事实摘要和有效期。跨条件/损坏/过期游标拒绝，翻页期间事实变化提示重新查询。销量只扣已退款冻结单位，避免付款后取消和退款重复扣减；只统计公开评价版本。
- 无结果：清空条件、真实品牌建议和求购入口。消费者提交时保存搜索条件，可查看自己的答复及撤回未结束记录；同一未结束内容去重，幂等重试，每用户滚动24小时最多20条新需求。求购不是订单，不扣款、不采购，不承诺上架或到货。
- 管理员：用户求购列表/状态筛选/详情，RBAC只读与处理权限、密码二次验证、版本及幂等控制；详情访问与处理审计，历史不可覆盖。商家无求购访问/处理权限。用户文本转义展示，退出清理和异步会话隔离。
- 数据/契约：V025新增加密求购记录及append-only变更历史；隐私结构152表/1217字段、25个迁移。现行OpenAPI3.1共331操作，其中本批12个新增或修改操作均具备实际响应覆盖；TypeScript/Dart生成一致性门禁。19个政策域与7类外部面仍待核验，不填造保留期限或删除授权。
- 消费者App/Web与管理员接入真实API，保留参考照片、圆角布局、字体许可与按钮动效。现有订单、售后、客服及当前粮提醒保持原有链路；本批不增加活动、降价、到货或求购通知生产者。

## 查询容量边界

沿用受验OpenSearch v1投影/别名、Outbox和补偿机制，不把不完整索引字段当商品事实。OpenSearch发现SKU身份，PostgreSQL只读可重复读事务完成事实校验、筛选、聚合及全结果排序，再分页。候选上限默认10,000（可控范围100–50,000）；超限明确503，不静默截断。搜索不可用时查询失败，但独立业务事务仍可提交，恢复后补偿。

这是当前小规模模拟目录方案，不代表大目录生产容量通过；后续需单独推进版本索引字段和性能验收。详细规则见[M6.8设计](M6.8-搜索与求购设计.md)。
