## 实现结果

- 同一 PostgreSQL 事务完成 Quote 当前事实校验、一次消费、按商户拆分子单、固定商品/标准/价格/地址/配送/优惠快照、汇总同 Offer 多行数量并预占库存与券、创建待支付意图、移除确认购物车项、审计和 Outbox。故障全部回滚。下单只能提交 quote_id；同键重试返回原结果，不同键不能再次消费同一 Quote。
- 按固定顺序锁购物车、Quote、商品项、Offer/库存、券。最后库存并发只能成功一次；跨商户库存不足全单回滚，Inventory Adjustment 不能侵占预占量。预占只增加 reserved_qty，不减少实物库存。
- 订单、子订单、商品项、地址、优惠快照和库存事件保存独立持久事实。数据库约束与不可覆盖触发器保护快照；延迟提交约束核对 Quote 归属/消费、子单金额守恒和 Payment 金额/币种/期限。
- 未付款整单取消需要消费者归属、If-Match、幂等键和显式确认；取消主单/逐项明细/事件是取消数量事实，cancelled_qty 是受证据约束的缓存。释放库存、恢复券原 AVAILABLE/RETURNED 状态或转 EXPIRED、关闭 Payment、取消父子单同事务，不产生退款或改写原金额。
- 付款窗口版本不可覆盖，默认 900 秒；管理员在 RBAC + 密码/TOTP reverify + audit 下发布 60–3600 秒新版本，既有订单期限不变。超时任务最多扫描 50 单，每单独立短事务、FOR UPDATE SKIP LOCKED；多 worker 与取消竞争父单锁，只释放一次。
- InventoryReservationChanged 通过真实 RabbitMQ 接入已有幂等商品事实 Consumer 和搜索投影；按不可覆盖事件来源校验，重复投递不重复改变投影版本。OrderCreated/OrderCancelled/OrderExpired 存于 durable quorum 队列，供后续支付/履约消费者接入。
- Flutter 接通冻结报价确认下单、我的订单/详情/商户分组/期限、未付款取消和登录回跳；退出/换账户清空私有数据并丢弃旧异步响应，网络失败保留原命令键。商家 Web 查询获授权子单，管理员 Web 查询父子订单并发布期限策略。
- 商家必须拥有 order.read 且全部订单项 merchant/store scope 匹配；默认范围另需 order.default-scope，混合子单任一项无权限则整单隐藏。本批商家接口不返回消费者地址。管理员读订单和配置期限分别使用 order.admin.read、order.policy.manage。
- 新增 10 个运行时操作，pawday-m4.2.yaml 共 **132 个已实现操作**；TypeScript/Dart DTO 和 client 再生成一致性、lint/bundle/validate 通过。

## 边界与下一步

模型与约束见 [M4.2 实现说明](M4.2-库存预占与订单.md)。当前只有 PENDING/CLOSED Payment 意图，没有渠道、PaymentAttempt 或支付成功入口；没有扣减实物库存、付款后部分取消/退款、履约/结算账本。后台暂不接收上述订单事件执行付款或履约。数据库状态迁移约束须在相应阶段显式扩展，不能伪造成功状态。

Android 为 debug APK；iOS 签名/设备验收、生产支付/短信/云存储、容量与恢复演练仍属后续准入。

下一步先评审合并 PR #8，再从合并后的主分支推进 **M4.3 模拟支付**：渠道属于 PaymentAttempt，支付意图可在安全核验后创建或切换 Attempt；实现模拟确认幂等、金额/币种校验、成功时预占转正式扣减及券核销、支付与取消/超时竞争、确认不确定时恢复查询/对账，避免重复扣减。完成后仍需履约、部分取消/退款、账本及 M4 总验收。每阶段均提供开发交付包、验收报告并同步实施计划。
