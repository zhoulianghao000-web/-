# M4.1 购物车与 Pricing Quote

从 M3.4 PR #6 合并后的主分支实施。基线：`e70a451ac072c403298df6e684c3718ff11bd454`。此阶段交付购物车、地址、不可变报价与基本配送配置，不创建订单、不预占库存、不锁券、不调用支付。

## 权威数据与身份

`carts/cart_items` 保存明确 Offer 和可选本人宠物，失效时拒绝或标为不可售，不替换商家。所有消费者命令按 user_id 归属检查；PATCH/DELETE 必须 If-Match，写命令必须 Idempotency-Key。同键异载荷 409；原键重试返回原结果。购物车操作按用户购物车锁串行，游客意图批量合并全成功或全回滚。Flutter 游客意图仅保存在当前应用内存，登录后服务端重新核验；合并失败保留原意图和命令键，尝试合并的用户变化会清空意图。

`user_addresses` 支持多个明确地址和版本化修改/软删除。省份使用名称选择；市、区县和门牌写入用户提供的完整 detail，结构化 city_code/district_code 可未知，不用省份代码伪造区县。当前配送规则按省份判断范围，不承诺区县级地理解析/地图校验或默认地址/标签维护；地图和后续地址增强按后续阶段推进。省级名称代码参考[政府网省级代码表](https://www.gov.cn/zhengce/2001-11/01/content_5720217.htm)，未引入该历史资料中的县级数据。

## 正式定价

规则引用 PostgreSQL 不可覆盖 `pricing_rule_versions` 中 `PRICING_V1_1 / LARGEST_REMAINDER_V1`。金额整数分；乘除使用 BigInteger 中间值；对外金额限制在 JSON 安全整数范围。行键按 `(merchant_id, offer_id, cart_item_id)` 规范字符串排序分配，重算不因请求列表顺序变化而改变尾差。

依次读取有效会员价、商品活动阶段、商家券、平台商品活动阶段、平台券、配送费用、运费优惠阶段；阶段分摊使用上一阶段余额。每商家最多一张商家券，整次试算最多一张平台商品券及一张运费券；门槛只计符合范围余额。优惠截断不超过余额；总应付为零时逆序撤回最后有效优惠一分并重放原有分摊，固定其他优惠总额及资格，不添加伪造费用。

当前在线数据适配接入已发布、未过期、属于本人、AVAILABLE/RETURNED 的基础商品券/运费券，以及已生效会员订阅。无商品活动和运费补贴发布模块时，这些阶段活动集合为空，不制造活动优惠。运营活动发布、发券、会员购买/退款/续费属于后续阶段；没有这些资格就拒绝客户端 use_membership 或券选择，不为了演示向生产用户授予资格。当前基础券适用整个商家/平台商品范围；品牌/品类/指定 SKU 券未发布，不扩大解释成基础券。后续引入这些范围时必须补齐独立契约和当前余额筛选测试。

`coupon_definitions/user_coupons` 分开定义发布状态和用户持券状态，保留 definition_version、reservation 字段；本阶段只读取资格，不执行完整券生命周期。`membership_plan_versions/membership_subscriptions` 保存引用、起止时间、状态和版本，只有有效资格选择 Offer 的当前 member_price_fen，无有效会员价的行仍取普通价。测试资格和来源全部由隔离测试库显式创建，不作为生产种子。

## 配送模板

管理员持 `pricing.shipping.manage` 权限，并完成密码 + TOTP action/session reverify 后发布不可覆盖 `shipping_rule_versions`；发布与审计同事务，命令幂等。每商家使用最新版本。基础运费 + 向上取整的商品总公斤数 × per_kg_fen；包邮门槛以商家商品活动后、扣券前的商品金额计算。当前没有已发布商品活动，基数就是会员/普通单价形成的商品金额。费用仅在每商家一组计一次。

模板缺失返回 SHIPPING_RULE_REQUIRED，地址不在范围返回 ADDRESS_OUTSIDE_DELIVERY_AREA，不默认包邮。不覆盖生产快递区县范围、超重特殊品运费、分仓模板等扩展能力；发布这些规则需新增版本契约和验收。本阶段选择基本省级/总重量模板，适合第一条纵向试算流程。

## 不可变 Quote 与失效

PostgreSQL 同事务持久化 `pricing_quotes`、items、merchant_groups 和 discount_allocations。冻结地址、会员、商品标准、Offer/购物车版本、单价数量、配送规则、优惠来源、各阶段基数与分摊、input_hash/snapshot_hash 以及 expiry。数据库拒绝快照改写；ACTIVE 仅能一次进入 CONSUMED/EXPIRED/INVALIDATED，消费订单引用唯一。当前没有消费 API，实际下单消费及库存/券预占统一留给 M4.2。

GET Quote 返回原冻结金额并校验当前依据；价格、购物车、地址、商品标准、宠物有效性、会员、优惠或配送模板改变时标 INVALIDATED，不静默采用新金额。库存不足也失效；库存总量变化但仍足够时不保证未来库存。过期任务分批 FOR UPDATE SKIP LOCKED，失败保留数据库事实下次重试。读取同时核验过期。原创建键重试保留同一历史响应，客户端应 GET 核对当前状态；重新试算使用新的命令键。

客户端退出、切换用户或请求世代变化会丢弃旧异步结果并清空私有 Quote。打开中的地址对话框也会遮去旧用户资料。Quote 在客户端超时后清空；可主动核对服务端状态。本阶段没有“支付/提交订单”按钮。

## 契约与验证

`openapi/pawday-m4.1.yaml` 为当前已实现机器契约，TypeScript 与 Dart 从此生成；原 M1 设计规范仍保留。CI 必须 lint/bundle/validate、验证实际响应和生成一致性，并运行后端、Web、Flutter 与真实四服务联调。

新增测试覆盖 2,000 组固定种子的整数分守恒/尾差排序、整数乘法溢出防护、零元拒绝、逆序撤回、后阶段门槛、跨商户运费唯一、幂等与并发、越权/乐观锁、优惠资格/槽位、快照不可改写、过期 worker、事实变动失效、游客原子合并、退出丢弃异步和私有地址隐藏。真实联调从管理员发布标准/商家库存报价，扩展至配送规则发布以及消费者加车、地址、试算、原键重试、数量改变失效与清理。

验收统计和 CI 原始证据将在通过后写入 `M4.1-验收报告.md`。M4.1 通过不能替代 M4 交易总验收；下一步从合并后的 M4.1 主分支实现库存预占、订单拆分、Quote 同事务消费和模拟支付。
