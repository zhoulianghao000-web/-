| 真实 OpenSearch health | 集群 green，health 实际访问 cluster/aliases/mapping；四服务整体 health=UP |
| mapping/version/alias 重复初始化 | 两次初始化同一物理索引与 ACTIVE 版本，严格 mapping 验证、读写别名一致 |
| 重复事件不会产生错误结果 | 三变化事件实际 AMQP 路径、重复投递、提交后 ack 前断 channel 重投递、稳定 ID/修订号和墓碑 |
| 搜索断开时事实仍提交 | 真 TCP 断开后 source+Outbox 提交、publisher confirm 成功，任务转 FAILED_RETRYABLE，health=DOWN |

| rebuild 失败保留旧搜索 | 完全不可达及实际 partial/poison 新索引失败均验证旧 read/write alias；修复后受控 retry 成功；alias 已切但 DB 未完成可恢复 |
| 完整开发环境实际健康 | 同一后端 health 响应 db/rabbit/redis/search 均 UP，不是分别截图或只测 client；Redis TTL 与不可达/恢复另测 |
| CI storage/search 集成门禁 | 已配置独立四服务 Compose health、强制同一 infrastructure-it profile、响应验收与失败证据；本地该 profile 已完整执行。**远程 CI 未执行：当前目录没有 Git 仓库/remote，待目标仓库** |

自动链路另启真实 Spring 实例，scheduler + publisher + Rabbit search listener + sync worker 自动完成事实提交 → broker → Inbox/task → OpenSearch，未手动 pump。两同步 worker 抢不同任务、租约失效旧 worker fenced；BUILDING 索引接收扫描后变化并保持最新事实。对账发现缺失/孤儿文档时采用新索引重建，不删除当前索引。搜索 retry/rebuild/reconcile 和原 Outbox replay 验证权限、动作绑定证明、幂等键、审计故障的同事务回滚。
