## 实现结果

- PaymentAttempt 持有微信/支付宝渠道和客户端平台；同一 Payment 同时最多一个活动尝试，最终成功渠道从成功 Attempt 派生。命令幂等键先核对，再安全关闭旧尝试，避免同键重试关闭自己的支付。
- 先提交支付意图，再在业务事务外调用持久化模拟 PaymentGateway。服务端查询成功后，在同一个 PostgreSQL 事务保存不可覆盖收款凭据、扣减实物/预占库存、CONSUME 和销售事件、核销冻结优惠券、推进 Payment/父子订单、审计和 Outbox。任一写入失败全部回滚，渠道事实仍在，恢复查询可补偿确认。
- 优惠券核销以 order_coupon_snapshots 冻结清单为准，缺少 RESERVED 归属则整笔确认失败。延迟提交约束核对渠道凭据、金额/币种、父子单、CONSUMED 预占对应销售流水和已核销券证据。
- 关闭/切换需渠道确认；UNKNOWN 保留库存和券，阻止取消和超时释放。支付恢复与订单超时扫描按安全顺序执行，待处理短间隔查询，未知结果指数退避最高 300 秒；多 worker 用 FOR UPDATE SKIP LOCKED 领取恢复计划，终态周期查询晚到收款。
- 金额或币种不符、晚到或重复收款保存原渠道凭据并建立异常 case，以固定退款号按原交易补偿；不会恢复已关闭订单或覆盖成功赢家。自动补偿最多 8 次，超限 NEEDS_REVIEW；管理员受 payment.read/payment.requery、密码/TOTP 二次验证、命令幂等和审计控制地重启核查，不能手工设置成功。
- Flutter 收银台支持本人订单、尝试/切换、查询、安全关闭、显式确认模拟成功/失败/未知；退出/换账号丢弃晚到私有响应。商家看到已付款待履约子单，管理员查询尝试/异常并受控核查，输入凭据用后清空。
- local 且非 production 启用模拟器；production 即使同时激活 local 且开启模拟 flag，也不注册模拟适配器或模拟端点。没有真实适配器时发起支付返回渠道不可用。
- OrderPaid 和支付尝试/异常/补偿事实接入 durable quorum 队列；库存事件沿既有幂等商品事实 Consumer 同步搜索。真实 MQ 不可用时付款业务事实可提交，恢复后补发；重复核对不会再次产生销售流水。
