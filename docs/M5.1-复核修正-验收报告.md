## 原交付核验与修正

九个原交付文件的大小和 SHA-256 与原验证 JSON 一致；三份源码 ZIP 与各自最终 Git 提交逐文件一致。原 M5.1 最终主分支的五个 Job 均 success。原报告后端数量 273 应为 272，各门禁实际合计 458，原 457 为统计错误；原始交付 JSON/ZIP 不覆盖，仓库历史报告加更正说明。

复核发现并修正的业务问题详见 [复核报告](M4.5-M5.1-复核报告.md)，核心包括：

- 退款 worker 加 PostgreSQL claim/lease 和 token fencing；查询原退款号后恢复；UNKNOWN 有限重试；FAILED_FINAL 可经管理员 RBAC、二次验证、幂等和审计恢复。迟到 worker 不能覆盖新结果，人工恢复保持原退款号。
- FAILED_FINAL 仍阻止提前返券；结算后多次退款持续进入调整账本；佣金和积分使用累计成功冻结商品额度分配尾差；结算等待 track 锁后重新检查售后冻结。
- 最新会员/兑换版本为权威，退休旧版不可继续购买/兑换；政策版本唯一；并发首单续费串行激活；签到按上海日期；参数类型和范围校验。
- 商品实付积分不扣原始运费；政策缺失明确拒绝业务确认，渠道已收款可在恢复配置后重查完成权益；积分账目统一账户锁，PointsChanged 与事实同事务写 Outbox。
- 18 类新增业务事件绑定持久 quorum 队列，mandatory 发布获得真实 broker confirm；修正开发包启动 JAR 路径和 APK 版本。新增管理员退款恢复入口保留准确的渠道核查提示。

迁移只新增 V016；不改已发布 V013–V015。退款租约字段留在服务端，不改变公开 DTO。库存、退款、结算、积分账本保持不可覆盖约束。
