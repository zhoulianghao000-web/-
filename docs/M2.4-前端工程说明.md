# Pawday M2.4 三端前端工程

基线：PR #1 已合并，主分支提交 `eed4da8c8f747e77f24a9db49c9feb0fd8c848a4`；M2.4 从此提交创建 `codex/pawday-m2.4`。

## 启动与门禁

Node 24、pnpm 11.25.0；Flutter 3.47.6 / Dart 3.13.5。依赖锁文件随仓库提交。

```sh
pnpm install --frozen-lockfile
pnpm generate:check
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm exec playwright test e2e/web.spec.ts
pnpm dev:merchant
# 另一个终端：pnpm dev:admin
```

商家端 `http://127.0.0.1:5173`，管理员端 `http://127.0.0.1:5174`。开发代理将 `/api` 转发至后端 `127.0.0.1:8080`；先运行仓库的 `scripts/init-local.ps1`、`scripts/start-local.ps1`。账号与 MFA 初始配置以这些脚本生成的本地资料为准，前端没有默认密码。管理员必须提供身份验证器当前 TOTP，敏感会话操作需要再次取得新的 TOTP。

```sh
cd consumer-app/flutter
flutter pub get --enforce-lockfile
flutter analyze
flutter test --coverage
flutter run --dart-define=PAWDAY_API_BASE=http://127.0.0.1:8080/api/v1
flutter build web --release --dart-define=PAWDAY_API_BASE=https://api.pawday.example/api/v1
flutter build apk --debug
```

Android 模拟器访问宿主后端使用 `http://10.0.2.2:8080/api/v1`；实体机需使用可达的开发地址。Release API 强制 HTTPS。示例 HTTPS 域名只用于验证构建，交付部署须替换为实际服务地址。Flutter Web 是开发预览/编译验证，消费者正式交付仍是移动 App。Android 包为开发 debug 包；iOS 工程已生成，设备签名与商店发布不属于 M2。

## 契约与边界

`openapi/pawday-m2.3.yaml` 是已实现、经 M2.3 验证的运行时契约；M1 设计契约保留未来业务接口。`pnpm generate` 生成共享 TypeScript paths/DTO 与 Flutter Dart DTO/路由常量。生成文件包含源文件 SHA256；`generate:check` 对两份输出逐字比较，不能手工修改生成文件。Dart 子集生成器遇到不支持的 schema 类型直接失败；新增复杂契约时需同步扩展生成器及测试。

TypeScript 客户端通过 `openapi-fetch` 使用生成的强类型 paths。客户端固定消费者/商家/管理员身份域，并阻止跨域传递 Bearer。GET 或声明幂等键的请求遇到 401 才允许刷新后重试；一次性 reverify 操作不会自动重放。调用方为一个业务意图保存同一幂等键；409 带请求编号返回，要求重新读取并确认。`If-Match` 辅助字段仅供采用该协议的未来接口使用，当前 RBAC 更新接口仍以契约中的请求体 `version` 为准。

Web access/refresh token 仅存内存，刷新页面须重新登录；localStorage 仅存各身份域设备 ID。移动端使用 `flutter_secure_storage` 保存消费者会话，恢复时校验 API 地址、身份域和服务端 principal。Flutter Web 预览仅使用内存存储。注销和认证响应通过会话代际保护；写入/删除安全存储串行执行，避免迟到响应复活会话。

商家门店由服务端授权列表与 merchant_id 决定，切换页面保留仍有效的当前门店。两 Web 端进入受保护路由重新读取 principal；前端 RBAC 仅提供界面与路由体验，后端鉴权仍是权威边界。审计页读取真实 `/admin/audit`，包含加载/空/失败状态。注销其他设备先取得 action 绑定的一次性 proof，再立即消费，proof 不展示、不落盘。

消费者五 Tab：首页、分类、宠物、附近、我的。游客可浏览公共壳；宠物和设备页面要求登录并保留安全内部 `returnTo`。手机号验证码请求走真实 OTP/Outbox 契约。当前宠物 context 校验登录用户与服务端所属宠物列表，退出/切换用户清空；宠物列表与商品领域 API 留待 M3，当前不伪造领域数据。

## CI 与真实联调

`frontend.yml` 的三个独立硬门禁为 Web、Flutter、真实三端/后端联调；原有 backend、OpenAPI、四服务集成门禁继续运行。Web 包含 lint/typecheck/unit/build 与 Chromium 页面测试；Flutter 包含 analyze/test/Web build/Android debug APK build。

真实联调 job 在隔离 Compose 实际启动 PostgreSQL、Redis、RabbitMQ、OpenSearch，启动现有后端并要求聚合 health 成功。浏览器验证真实商家门店隔离、refresh、跨身份域拒绝、管理员 TOTP 与审计响应；Dart 通过真实 HTTP 请求 OTP，等待 RabbitMQ 消费者写入测试短信，再验证登录、refresh、恢复、设备列表和注销。缺少环境或基础设施会失败，真实联调不降级为 mock。测试专用密钥仅属于隔离 CI fixture。

前端页面 fixture 测试用于确定性验证 UI/错误/重验证分支，不替代真实联调。验收必须记录 CI 的实际结果，配置存在本身不等于通过。
