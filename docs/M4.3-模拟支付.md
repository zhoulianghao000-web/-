# M4.3 模拟支付

基线：M4.2 PR #8 合并提交 `c304394c3499dd0cdc8d599fcc61d9de3c79baf8`。此阶段不接真实微信/支付宝，不发生真实扣款。

## 状态和权威事实

Payment 聚合应付金额、币种、付款期限和最终成功凭据。PaymentAttempt 持有渠道和客户端平台，同一 Payment 同时最多一个 CREATED / CHANNEL_PENDING / UNKNOWN 尝试。成功渠道从 successful_attempt_id 派生，不能覆盖旧收款。

发起尝试先提交 PostgreSQL 意图，再在事务外调用 PaymentGateway。开发适配器把模拟渠道事实持久化在独立事务中，禁止在业务事务内进行渠道 I/O。服务端查询确认后，同一事务写入不可覆盖收款凭据、库存 CONSUME / 销售流水、优惠券核销、Payment SUCCEEDED、父订单 FULFILLING、子订单 PAID_WAITING_FULFILLMENT，以及 Outbox / 审计。客户端模拟命令只能选受控结果，不能指定应付金额或币种；页面结果来自服务端查询。

## 安全关闭与恢复

关闭及切换尝试必须先向渠道确认旧尝试已关闭或失败。UNKNOWN 继续保留库存和优惠券，不能超时释放。到期扫描先恢复支付，再只关闭确认安全的 PENDING Payment。待处理尝试每 5 秒查询；未知结果指数退避，最高 300 秒；终态每 30 分钟复核晚到收款。多个扫描器通过 PostgreSQL FOR UPDATE SKIP LOCKED 领取下一查询时间，领取后保留 30 秒恢复窗口。

金额/币种不一致、已关闭订单晚到收款或第二次收款：保存实际渠道凭据，建立异常 case，以固定退款号按原交易补偿，不恢复订单、不改写赢家。补偿失败最多自动尝试 8 次，指数退避最高 300 秒，超限 NEEDS_REVIEW。管理员核查需要 payment.read / payment.requery、密码/TOTP 二次验证和审计，可重启补偿；不能直接改为付款成功。模拟渠道退款幂等，业务提交失败后可安全重复查询。

## 三端和运行配置

Flutter：本人订单进入收银台、微信/支付宝尝试、查询、安全关闭；模拟成功/失败/未知须显式确认。退出或账号变化立即清除私有支付信息并丢弃晚到响应。商家订单展示已付款待履约；管理员订单详情可查询尝试及异常，并受控核查。

local 且非 production 默认启用模拟适配器。production 即使同时启用 local 或设置 simulation-enabled=true，也不注册模拟适配器/端点。真实渠道未配置时，发起支付返回 PAYMENT_PROVIDER_UNAVAILABLE。V011 创建渠道尝试、凭据、核销流水、异常 case 和恢复计划；业务快照只保留引用和金额事实。

新运行时契约 `openapi/pawday-m4.3.yaml`，140 个已实现操作；TypeScript / Dart DTO 从同一契约生成。新增支付事实持久化到 `pawday.payment.facts`，OrderPaid 到 `pawday.order.facts`，库存事实沿既有幂等投影同步搜索；履约消费者在后续阶段接入。
