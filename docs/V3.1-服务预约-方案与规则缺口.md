## 本批工程规则

- 仅洗护、寄养两个非医疗类别，服务有名称、门店、类型、ACTIVE/PAUSED 和版本；不接受价格、医疗类别或额外字段。附近资料中的服务标签不直接当作可售项目。
- 时段起止时间和容量不可变，同一服务时段不可重叠。开始在未来 90 天以内，时长不超过 7 天，容量 1–100。这是工程边界，不代表真实门店排班规则。
- 一份预约占一个服务时段名额，不同服务独立计数；尚不处理共享美容师、笼位、店面总容量和寄养按晚库存。寄养按整个起止区间进行一次模拟。
- 新预约只接受 ACTIVE 商家、公开且认领已核实门店、ACTIVE 服务和未开始时段。门店后来隐藏不影响消费者读取和在开始前取消自己的已有预约。
- 本批只有 `BOOKED → CANCELLED`；消费者操作自己的记录，商家操作当前授权门店的记录。取消释放名额且保留原记录，之后可重新预约。开始后不允许本批自助取消，后续由履约规则处理。
- 保留服务名称和政策快照，固定 `SIMULATION_NO_CHARGE_V1`，金额强制为 0。0 代表没有收费行为，不是实际门店免费服务的宣传。不创建支付、退款、商品订单、财务或结算记录。
- 复用现有身份、门店范围、`store.read` / `store.nearby.write`、幂等事务、版本冲突和审计。不保存宠物照片、健康信息或联系方式；商家只得到预约编号、服务、时段和状态，实际身份核验属后续批次。
- V028 新增服务、时段、预约表，不改写 V1/V2 数据，不预造预约。数据库约束金额为 0，时段不可变；预约除一次取消外不可修改/删除。预约和取消锁同一时段，避免最后名额超售和释放计数漂移。
- 默认关闭；显式 `PAWDAY_BOOKING_SIMULATION_ENABLED=true` 且 deployment-mode 为 development/test/pilot 才可使用。production/prod profile 拒绝；模拟试点暂停时拒绝。源码更新不自动开启桌面功能。

## 页面及契约

商家 Web 新增“服务预约演练”，维护服务、暂停/恢复、时段、剩余名额和预约取消。消费者 Flutter 新增 `/service-bookings`，模拟环境可从附近门店或“我的模拟预约”进入。时间按本机时区展示，明确标识模拟、不收费。请求失败重试保留幂等键；换账号/门店不恢复迟到的旧数据。安卓仍只有消费者，不构建商家或平台安卓。

技术接口仍在 `/api/v1`；产品 V3 不要求改变 API 主版本。`openapi/pawday-v3.1.yaml` 描述 12 个新操作并生成 TS/Dart 类型：

| 方法及路径（省略 /api/v1） | 作用 |
|---|---|
| GET/POST `/merchant/stores/{store_id}/booking-services` | 服务列表/新增 |
| PUT `/merchant/booking-services/{id}/state` | 带版本暂停/恢复 |
| GET/POST `/merchant/booking-services/{id}/slots` | 时段列表/新增 |
| GET `/consumer/stores/{store_id}/booking-services` | 公开门店可用服务 |
| GET `/consumer/booking-services/{id}/slots` | 未来时段和名额 |
| GET/POST `/consumer/service-bookings` | 自己的预约/新增预约 |
| POST `/consumer/service-bookings/{id}/cancel` | 带版本取消 |
| GET `/merchant/stores/{store_id}/service-bookings` | 授权门店预约 |
| POST `/merchant/stores/{store_id}/service-bookings/{id}/cancel` | 带版本取消本店预约 |

列表分页，单页最多 100 条；写请求需要幂等键，状态修改需要 If-Match，业务数据均标识 simulated=true。

## 真实业务规则缺口

| 事项 | 当前事实 | 后续依据 |
|---|---|---|
| 合作门店 | 仅合成工程门店，未收到真实合作证据 | 授权、服务、资质及责任范围 |
| 适用与容量 | 一份一个名额，各服务独立时段 | 物种/年龄/体型、多宠、共享人员/笼位、营业休息 |
| 价格 | 不收费，金额强制 0 | 单次/按晚、押金、优惠、变更和金额确认 |
| 取消退款 | 开始前无费用取消的工程演练 | 提前窗口、费用、商家取消、退款时限、未到店和争议 |
| 核销履约 | 未实现核销或完成状态 | 身份、一次性凭证、有效期、到离店、异常流程 |
| 结算 | 不产生财务流水 | 归属、佣金、账期、退款追溯与对账 |

## 验收

真实 PostgreSQL/HTTP 验证最后名额竞争、重放/键冲突、取消释放、跨身份和门店/权限撤销、门店隐藏/暂停/停用、时间/分页边界、不可变事实、默认关闭/生产拒绝。升级测试从 V027 升至 V028，证明既有门店保留且无新造预约。

页面测试验证权限控件、凭证/版本、切换门店与退出清理。真实浏览器联调验证商家表单写入、消费者预约/取消、同身份持久回读与容量恢复。完整 CI 回归既有功能并验证 Web、Flutter 和消费者 APK 稳定签名。生产材料继续留白，手机保留用户已手动安装 V2 的历史确认，本批不操作手机。
