# V3.1.1 模拟服务预约：启动与验证说明

本批是服务预约的首批工程交付，包含模拟服务、时段、预约和取消；正式收费、核销、退款及结算不在本批。安卓仅消费者，商家与平台继续使用 Web。

## 当前桌面与交付包

当前 `C:/Users/zl/Desktop/PawdayV1` 的已验收 V2 程序保留。V3 开发包解压到**另一个目录**进行评审，不覆盖原目录，不复制、打包或公开 `.pilot` 私有配置。独立目录由现有启动器生成自己的环境与数据。交付验证记录将核对原 V2 APK/JAR 未变。

开发包包含 Windows Java/Node 运行时、同提交的后端、三端 Web 和消费者 APK；源码包不含运行时。延续现有 Docker Desktop 环境要求。商家 Android、商家 App 预览和平台 Android 不在交付包。

## 在独立目录开启模拟预约

1. 当前 V2 与候选目录使用相同本机端口，不能同时启动。确需评审候选程序时，先通过原 V2 的停止入口停止原环境；数据和账号由原启动器保留。本文档的生成没有执行这一步。
2. 在独立解压目录使用现有 `启动PawdayV1.cmd` 初始化并启动一次，再使用该目录自己的 `停止PawdayV1.cmd` 停止候选程序。
3. 在**候选目录**生成的 `.pilot/desktop-*/config.env` 中增加一行 `PAWDAY_BOOKING_SIMULATION_ENABLED=true`，然后重新启动候选目录。不要改原 V2 配置，不要把私有配置提交到源码库或交付包。仅修改父终端环境变量不会覆盖启动器的隔离配置读取。
4. 商家 Web 的“服务预约演练”维护当前授权门店的服务和时段；消费者 Web/消费者 App 的模拟附近门店入口可进入服务预约，也可查看“我的模拟预约”。服务、时段和预约都显示模拟标识；已有公开、认领已核实门店才可被消费者选择。
5. 如需回到 V2，先通过**候选目录自己的停止入口**停止候选环境，再从原 V2 目录启动。不要把 V2 JAR 放回已升级的候选数据库，也不要移动/覆盖两套私有数据目录。

对开发者直接启动的后端，等价配置为 `--pawday.booking.simulation-enabled=true`，仍必须运行在 development/test/pilot 环境；production/prod profile 拒绝。模拟试点暂停时也会拒绝预约功能。

当前用户没有提供真实合作门店的价格、取消退款和履约结算规则，本批没有开通真实交易。金额 0 表示不发生收费，并非真实门店免费服务的承诺。

## 验证动作

- 商家选择授权门店，新增洗护/寄养服务和未来时段；同服务重叠时段应被拒绝，已保存时段不可改写。
- 消费者选择服务，确认模拟预约，在“我的模拟预约”读取记录；一份预约占一个名额，重复提交不会重复占位。
- 消费者或授权商家在时段开始前取消，记录保留为已取消，名额恢复。服务暂停/门店隐藏后不接受新预约，但已有预约仍能被拥有者读取并在开始前取消。
- 切换账号或商家门店，旧记录和迟到响应不应出现在新上下文中。只读商家不显示写操作；其他门店/消费者不得读取或取消他人预约。

最终受测提交、实际响应数量、测试/CI 与交付哈希以同目录验收报告和 `V3.1.1-交付验证.json` 为准。开发包是可供独立评审的候选程序；不能从“文件已交付”推导出“当前桌面已更新”或“手机已验证”。
