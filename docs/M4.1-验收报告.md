## 实现与验收结果

- 消费者购物车固定明确 Offer、数量及可选本人宠物；按用户检查归属，写操作幂等，修改/删除要求版本。游客意图登录后重新核验，批量合并全成功或全回滚；失败保留原意图和命令键，不替换商家。
- 地址支持多条、版本化修改和软删除。Flutter 以名称选择省份，完整 detail 保留用户填写的市、区县及门牌；未知结构化区县代码保持未知。
- PostgreSQL 同事务保存 Pricing Quote、行、商户配送组及优惠分摊。冻结地址、资格、商品标准、Offer、数量、单价、规则、优惠来源和有效期。不可覆盖快照；事实改变后 INVALIDATED，过期 EXPIRED，读取保持原金额，不静默重算。定时过期任务分批抢占，失败可再次执行。
- `PRICING_V1_1 / LARGEST_REMAINDER_V1` 使用整数分、稳定行键和大整数乘除。资格与门槛以服务端事实为准；商家券每商家一张、平台商品券与运费券各一张。优惠不超过余额；零实付时撤回最后有效优惠一分，保持其他优惠资格和总额。2,000 组固定种子性质校验检验金额守恒、边界及排序稳定性，计为一项测试，不扩大测试数量。
- 有效会员订阅和已发布基础券作为资格输入；本阶段不向真实用户自动发券或授予会员。商品活动/运费补贴尚无发布模块，相关活动集合为空。基础券只支持整个商家/平台范围，不声称已支持品牌、品类或指定 SKU 券。
- 管理员在 `pricing.shipping.manage`、密码 + TOTP 二次验证及审计约束下发布不可覆盖配送规则。省级范围、总重量计费及包邮门槛由版本化数据配置；模板缺失/不支持地址明确拒绝，不默认包邮。跨商家每组只收一次运费。
- Flutter 商品详情接通加车、登录回跳、购物车、地址、权益选择、试算及核对。退出/换用户后私有数据及旧异步结果清空，打开中的地址对话框也隐藏旧资料。重新试算使用新命令键；网络失败重试保留原键。管理员端已接通配送配置页。
- 新增 14 个运行时接口，`pawday-m4.1.yaml` 共 **122 个已实现操作**；TypeScript / Dart 客户端生成一致性、lint/bundle/validate 通过。
