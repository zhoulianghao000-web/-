# M3.4 确定性适配与搜索闭环

从 M3.3 PR #5 合并提交 `f31f57bd663c316ec85163ecb4568b5fc7951ebb` 创建 `codex/pawday-m3.4`。运行时契约 `openapi/pawday-m3.4.yaml` 包含 108 个操作，共享 TypeScript/Dart DTO 从契约生成。

## 消费者流程

Flutter 首页进入分类，支持五类宠物筛选、商品名/品牌/SKU 关键词、游标翻页、商品详情、当前在售报价、来源/配料/营养资料和 2–4 个 SKU 比较。游客可以浏览；适配和比较使用消费者身份，服务端核对宠物归属。无当前宠物时不生成适配结论。交易报价不包含尚未确定的运费、优惠和实付；加车及结账属于 M4。

`pawday-fit-1` 是确定性规则版本，响应同时引用商品标准版本、宠物版本和年龄阶段 ID。分类、明确过敏原或有当前证据的年龄阶段冲突返回 `NOT_RECOMMENDED`，冲突优先于任何信息不足。未知生日/过敏状态、未评估的商品过敏原、缺失配料/营养、缺失或过期阶段资料、自由文本忌口返回 `INSUFFICIENT_DATA`。全部核对通过才返回 `SUITABLE`，该结果表示符合已核对条件，不是诊断或完整营养推荐。广告、会员身份、价格和 AI 不参与计算。

商品/阶段标准为不可变版本。新阶段规则发布后，旧商品阶段引用不被猜测性映射；需要重新核对商品资料。客户端清空异步旧响应，服务端强制归属检查，资料在请求间更新时要求刷新。

## 业务搜索投影

消费 M3.2 `pawday.catalog.standard-published` 与 M3.3 `pawday.offer.facts` 中的事实事件；`catalog-business-facts-v1 + event_id` inbox 去重，校验事件版本、载荷和数据库引用，按当前 PostgreSQL 事实重新派生。派生行和规范搜索事件在同一事务提交，再经既有 Outbox confirm、搜索 inbox、带外部版本的 worker 写 OpenSearch。

按 SKU 的事务 advisory lock 位于读取事实之前，避免两个投影 worker 将旧读取结果覆盖为新版本。比较完整派生文档后才创建新 revision；重复事件、乱序事件、定期扫描均不会重复创建相同变化。报价最低值来自当前 ACTIVE Offer，商户计数按商户去重，库存来自 `available_qty`；没有有效报价或商品退出发布时写 tombstone。没有伪造商品价格、库存和商户数量。

每 30 秒扫描最多 100 个真实 SKU，游标可循环，进程重启从头开始，用于历史数据、商户停用和遗漏变化补偿。全量 rebuild 仍使用 M2.3 新索引校验后原子切 alias；失败保留旧索引。搜索服务故障不回滚商品/Offer/库存事实；业务 inbox 失败使用有限退避和 DEAD/DLQ，并复用管理员 RBAC + reverify + audit 的受控 replay。

公开搜索真正查询 OpenSearch read alias，并重新查询 PostgreSQL 中的标准和 ACTIVE Offer。冻结/下架/停用的报价不会从旧搜索结果泄露。第一版按 SKU 稳定游标排序，关键词在当前标准的商品名/品牌/SKU 上二次过滤，因此可能产生稀疏或空页面，客户端保留下一页；未实现相关性推荐、广告或个性化排序。搜索不可用返回明确 503，不伪造搜索结果；商品标准和报价详情仍可从 PostgreSQL 读取。
