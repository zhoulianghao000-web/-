# M3.2 标准商品与审核

基线：M3.1 PR #3 已合并，main `8367c275e22c7c7a6939e250497074d56c838517`。M3.2 从此创建 `codex/pawday-m3.2`。

## 本批流程

管理员经 RBAC、密码/TOTP 二次验证建立品牌、SPU、SKU。平台根据标签、授权文件等真实来源创建标准资料草稿，明确配料原始顺序、营养标示基准/上下界、过敏原是否已知、适用阶段、来源和来源日期，再显式发布。历史版本和版本过敏原在数据库中禁止覆盖或删除；新发布退休旧版本，不修改旧版本内容。

商家只能读取当前已发布资料，不能读取平台草稿；提交纠错申请时记录所属商户、员工、目标 SKU 及其当时版本。申请不修改标准库。管理员有理由地批准或驳回，一次性决定；批准产生并发布新的标准版本，保存审核记录。SKU 在等待期间变化时返回 409，须重新核对并提交申请。

所有写入使用事务幂等，版本敏感命令使用带引号的 If-Match。敏感平台写入消耗当前会话、指定 action 的一次性 reverify。审计、资料、审核结果、Outbox 与幂等结果在同一事务提交；审计失败全部回滚。未知营养、适用阶段、过敏情况不自动补造。

商家和管理员 `/catalog` 页面提供建档、来源资料展示、纠错及审核；管理员还提供草稿发布、文件预览和确认。页面沿用会话 refresh、RBAC 与 request ID 错误显示，失败重试保持同一幂等命令。

## 导入模板

接受单工作表 XLSX 或 UTF-8 CSV。表头必须依次为 `sku_code,standard_json`，每行仅两个字段。仅导入已有 SKU 的标准资料新版本，品牌/SPU/SKU 用建档流程建立；不按同名商品自动猜测身份。最多 200 行、文件 2 MB、ZIP 总展开 8 MB。CSV 支持双引号、双引号转义和字段内换行；XLSX 支持 shared strings/inline strings，拒绝公式、宏、外部链接、多工作表、路径穿越和 DTD/外部实体。

`standard_json` 内容如下（全部为测试结构示例，不能作真实商品来源）：

```json
{
  "ingredients": ["TEST-ONLY ingredient"],
  "nutrients": [{"name":"protein","value_milli":26000,"unit":"PERCENT","basis":"AS_FED","qualifier":"MIN"}],
  "allergens_known": false,
  "allergen_ids": [],
  "life_stage_ids": [],
  "source_refs": ["TEST-ONLY label fixture, not real merchandise"],
  "source_updated_on": "2026-10-01"
}
```

营养值以标示数值的千分之一为整数存储（26% 为 26000）；单位为 PERCENT、MG_PER_KG、G_PER_KG、KCAL_PER_KG，基准为 AS_FED/DRY_MATTER，界限为 MIN/MAX/EXACT。过敏原和生命周期 ID 必须来自平台词典，阶段须属于该商品宠物类别；发布时重新核对有效性。

上传解析后持久化逐行预览、错误原因和 SKU 基线版本。重复行、未知 SKU、非法来源/数值/词典项会阻止整批确认；确认前不修改标准库。确认时按稳定顺序锁 SKU、再次校验所有行，整批事务发布；任何行失败回滚全部。预览过期不会静默覆盖新资料。确认/取消具有版本、幂等、RBAC、reverify 和审计保护，GET 可恢复批次状态。

## 事件与阶段边界

本批发布同事务写入 `CatalogStandardPublished`（SKU/资料版本引用）。不虚构 Offer、价格、库存或在售搜索文档；真实 `CatalogPublished` + Offer/库存投影闭环按 M3.4 落实。现有四基础服务集成门禁继续运行，搜索故障不参与标准库事务。

未接入真实首发商品来源；数据库没有真实商品种子，也不会把测试夹具当作上线数据。来源真实性与授权由平台运营审核，系统验证结构和版本保留，不声称自动核验标签事实。新品建档由平台完成，商家本批申请范围是已有 SKU 纠错。大批量异步导入、其他列布局/宏/多工作表模板不在本批范围。下一批 M3.3 做商家 Offer 与库存 Adjustment，M3.4 再做确定性适配和商品搜索业务验收。
