# Pawday M6.1 生产准入盘点与工程门禁启动说明

交付版本：0.6.1。后端项目版本：0.6.1-SNAPSHOT；Android 应用版本：0.6.1，build 7。包含此前交易、会员积分、评价内容、人工客服、私有图片/卡片、消息中心、七类提醒偏好，以及附近门店、定位授权/拒绝与高德目的地交接。本阶段增加 DeepSeek 证据解释、购买周期额度和隐私控制；通过 M5 总验收后再进行 M6 生产准入。

## 后端与四服务

需要 Java 21、Docker Desktop（Linux containers）与 Docker Compose。解压 Development ZIP 到独立目录，保持 `release/pawday-backend.jar`、`scripts`、`compose.yaml` 的相对位置。在解压根目录打开 PowerShell：

```powershell
./scripts/init-local.ps1
./scripts/start-local.ps1
```

第一个脚本仅在首次启动时执行，生成 `.env.local` 和 `.local-authenticator.txt`。第二个脚本等待 PostgreSQL、Redis、RabbitMQ、OpenSearch 健康后运行包内 JAR；开发包无需 Maven。源码包构建需 Maven 3.9+：`mvn -B -ntp -f backend/pom.xml -DskipTests package`。

后端监听 `http://127.0.0.1:8080`，聚合健康检查为 `/actuator/health`；Compose 端口分别是 5432、6379、5672/15672、9200/9600。已有服务占用端口时，须一致调整 Compose 映射及 `.env.local` 中对应服务地址。Flyway 自动执行到 V020；已发布 V001–V019 保持原校验和。不要手工清库或修改历史迁移，测试场景中的 TRUNCATE 仅用于隔离验收数据库。已有本地数据库应保留原密钥配置，不能重新生成密钥后继续使用旧密文。

商家演示账号 `local-staff-a` / `local-staff-b`，管理员 `local-admin`；随机密码在 `.env.local`。按 `.local-authenticator.txt` 中 Base32 密钥配置身份验证器。管理员登录与敏感操作需要 TOTP；同一时间窗的验证码只可用一次，二次验证须等待新验证码。开发短信由真实 Outbox/RabbitMQ 异步写入 `.local-sms`，消费者手机号登录使用该测试验证码。

## 商家与管理端

需要 Node 24、pnpm 11.25.0。在解压根目录：

```powershell
pnpm install --frozen-lockfile
pnpm dev:merchant
```

另一个终端执行 `pnpm dev:admin`。商家端 `http://127.0.0.1:5173`，管理员端 `http://127.0.0.1:5174`，开发代理转发到 8080。包内 `release/merchant-web`、`release/admin-web` 是经 CI 验证的静态构建；部署这些目录时需配置 `/api` 反向代理到后端。退款页对有 `payment.requery` 权限的管理员提供失败退款恢复入口，经密码/TOTP 二次验证后按原退款号核查渠道事实并恢复处理。

## Android 消费者端

另附 debug APK 来自本阶段通过门禁的 Flutter CI，应用版本核验为 0.6.1+7。该 APK 默认 API 地址为 `http://127.0.0.1:8080/api/v1`。连接开发电脑的 Android 设备/模拟器后，可使用 Android platform-tools：

```powershell
adb install -r Pawday-M6.1-Consumer-0.6.1-debug.apk
adb reverse tcp:8080 tcp:8080
```

设备连接与后端必须保持运行。需要直接使用 Android 模拟器宿主地址时，从源码重建：

```powershell
cd consumer-app/flutter
flutter pub get --enforce-lockfile
flutter run --dart-define=PAWDAY_API_BASE=http://10.0.2.2:8080/api/v1
```

实体机无线连接须使用可达的开发地址并相应配置后端监听；生产 release 使用实际 HTTPS 服务地址。Flutter Web 的示例 HTTPS 域名用于构建验证，不能当成已部署的生产服务。iOS 签名/设备验收仍在后续范围。

## 既有评价与内容流程

消费者在真实下单、模拟付款、商家发货并显式确认收货后，从“我的 → 订单 → 订单项 → 评价”进入编辑；也可在“我的评价”查看或修订。尚未收货、有进行中售后或已无未退款收货数量时不能首次提交。允许 PNG/JPEG 图片和 H.264 MP4 短视频，单文件最多 5 MiB、视频最多 120 秒、每条最多 6 个媒体。客户端选择文件后通过服务端凭证上传；数据库仅保存对象引用。宠物标签默认关闭，开启后只公开粗粒度物种/品种/年龄，撤销立即隐藏标签。

管理员在“评价”页查看待审内容，密码/TOTP 二次验证后通过、驳回或隐藏。通过审核按父订单奖励一次基本积分和一次媒体增量；默认规则为 10 + 5，管理员可发布新规则，旧订单仍使用冻结规则。退款按冻结规则累计比例追回，可产生负余额，负余额仍不能兑换。商家“评价”页须选择已获授权门店，仅展示该范围的公开评价。

管理员在“知识内容”页创建纯文本稿件，填写来源与显式推广标识、选择当前已发布 SKU，可上传图片。保存 → 提交审核 → 二次验证发布。旧已发布版本在修订待审期间继续展示；隐藏后公开内容和媒体均不可访问。消费者首页“知识”入口允许游客访问；登录用户可结合当前宠物查看挂载商品的既有适配结果。

媒体引用过的对象因保留不可覆盖历史证据而不能直接删除。短视频适配器只验证受限 MP4/H.264 文件结构；生产内容检测、转码/CDN 和隐私删除流程仍须在 M6 接入，不能把开发适配器视作生产媒体平台。

## 验证与停止

完整基础设施故障门禁执行 `./scripts/test-infrastructure.ps1`，使用隔离的真实四服务，不以 mock 代替。前端门禁命令及真实联调环境见 `docs/M2.4-前端工程说明.md` 和 `.github/workflows/frontend.yml`。

停止后端使用该终端 Ctrl+C；四服务使用 `docker compose stop`。本交付保留数据库/媒体/密钥文件，不需要删除卷。当前支付、退款和结算为开发模拟渠道；生产接入及恢复演练按 M6 执行。

## M5.3 客服消息使用

消费者“我的 → 人工客服”联系爪日平台；在商品商家报价或订单“联系订单客服”进入对应门店会话。登录后保留入口上下文，可发送文字、受控图片与当前商品/订单卡片。失败发送保留内容，重试继续使用原消息幂等键；图片上传失败需重新选择受控凭证。

商家选择授权门店后进入“人工客服”，管理员进入“人工客服”查看平台队列。领取/转接需要当前密码（管理员另需新 TOTP），只能分配到同范围且有客服读/回复权限的员工。未分配给自己的客服只能看到队列元数据；订单卡片另需订单权限。“关闭会话”后必须重新打开才能发新消息。

消费者“我的 → 消息与提醒”按七类查看消息与分别设置偏好，系统推送尚未接入，不需提前索取 OS 通知权限。RabbitMQ 停机时消息保存和授权读取仍可用，传输确认及通知会延后；恢复后 Outbox 自动补齐。管理员已有 Outbox 运维 API 可对 DEAD 事件按 RBAC、二次验证、审计安全重放。

本批额外门禁：`pnpm generate:check`、`python openapi/validate_m53_contract.py`、`mvn -f backend/pom.xml -Pinfrastructure-it verify`。CI 必须运行 SupportDeliveryIT 的真实 RabbitMQ 停机/确认丢失/ack 崩溃/并发/poison/DLQ/重放；本机无 Docker 不得改成 mock 验收。

## 既有附近门店与导航

商家登录后选择授权门店，在“附近资料”填写城市、地点类别、门店地址、电话、营业信息、GPS/WGS84 坐标与可用服务。不会自动创建虚构门店或伪装高德 POI；必须使用真实来源并让管理员审核。不要直接复制高德坐标拾取器的 GCJ-02 坐标。保存后状态为草稿，资料变更撤回旧公开结果。

管理员在“附近审核”选择门店，核对认领与资质、设置公开/隐藏、认领核实/拒绝及认证，填写审核依据与原因，然后用密码和新时间窗 TOTP 提交。公开必须先核实认领，认证须另核实资质；审核不可删除覆盖。权限不足时不显示命令，服务端再次校验。

消费者“附近”允许游客访问；按城市浏览无需位置授权。点击“使用本次位置”才请求前台定位，查询约 10 km 范围并按直线距离排序。拒绝、永久拒绝、定位服务关闭、超时均可改为城市浏览。Android 模拟器可通过模拟定位设置 GPS 数据，实体设备需要开启定位服务；Web 需可信来源/HTTPS（loopback 用于开发）。浏览器或系统权限调整后再次点击定位。

点击门店看地址、电话、营业信息、可用服务与来源；可联系门店客服，登录后保留门店入口。可用服务不是在线预约名额，营业信息需联系门店确认。宠物医院只有基本地点/服务信息，没有医疗诊断或疗效排序。

“交给高德导航”把已公开门店的目的地交给官方 HTTPS 地点页面，尝试唤起高德，无法交接则显示手动搜索提示。高德页面负责选出行方式和导航。没有向高德发送 Pawday 查询中的用户起点，也没有内置地图 SDK/API key。服务端可通过启动参数 `--pawday.nearby.navigation-enabled=false` 关闭交接，此时返回明确的 provider 不可用；三端不需要填写密钥。生产地图 SDK/外部 POI 接入要单独评审。

额外门禁：`python openapi/validate_m54_contract.py`、`pnpm generate:check`、`mvn -f backend/pom.xml -Pinfrastructure-it verify`。CI 的 NearbyDeliveryIT 使用真实 RabbitMQ stop/start 和 confirm；实际 Flutter Web/Chromium 测试授权定位与拒绝后的城市浏览；`scripts/check-amap-handoff.py` 验证真实高德 HTTPS 响应。实体手机已安装/未安装高德与 iOS 签名验收仍按 M6 执行，不能把浏览器验收当作手机验收。

## M5.5 AI 服务与三个客户端

默认未配置供应商密钥时，消费者仍可浏览商品、使用交易/宠物/客服功能，AI 页面显示暂时不能发送；管理员显示“尚未配置供应商凭证”。不使用伪造模型回答冒充在线服务。

真实 DeepSeek 接入由服务端设置 `PAWDAY_DEEPSEEK_API_KEY`，默认 `PAWDAY_DEEPSEEK_MODEL=deepseek-flash`。可以在私有 `.env.local` 中配置后重新启动后端；不要上传密钥、加入 App 或截图记录。供应商网络必须能访问官方 HTTPS endpoint。配置凭证不等于云端效果验收通过，M6 需单独记录真实推理、费用、限流和生产隐私验证。

消费者首页 → AI 商品资料解释：登录后查看额度；个性化默认关闭，选择自己的宠物并开启授权后才结合宠物解释。最多三个 SKU，支持“30元以内”等明确预算。问题/历史会话可查看、主动清除；资料建议显示旧值→新值，只有确认才保存，版本冲突先重新读取。清除聊天不会撤回已确认保存的宠物事实。

管理员 → AI 资料解释：可查看启用提示、灰度、额度策略和边界验证记录。新建提示版本后运行边界验证，再按配置版本灰度/启用；回滚须为真实发布过的版本。每项变更需新的密码/TOTP 二次验证。普通日额度与会员日安全上限均可动态配置；会员 20 次/月、300 次/年按已付款订单购买周期冻结，续费额度从旧周期到期开始，不能按天重置。普通免费余额优先消耗，页面分别显示免费与购买周期余额。

商家 → AI 资料解释：提供标准商品资料与报价库存的维护入口和说明，无消费者聊天读取权限。

本地重现 CI 协议联调可在独立测试环境执行 `python scripts/ai-provider-fixture.py --test-only`，并给后端设置 `PAWDAY_DEEPSEEK_API_KEY=TEST_ONLY_M55_PROTOCOL`、`PAWDAY_DEEPSEEK_URL=http://127.0.0.1:9195/chat/completions`、`PAWDAY_AI_ALLOW_LOOPBACK=true`。这是 HTTP 协议测试服务，不是真实 DeepSeek 推理。正式环境不得启用该测试选项。故障/事务门禁为 `mvn -B -ntp -f backend/pom.xml -Dtest=AiIntegrationTests test`；完整 CI 还运行四服务与三端实际 HTTP 流程。

指标包括 `pawday.ai.quota.requests`（按 RESERVED/CONSUMED/RELEASED）、`pawday.ai.quota.expired.leases`。应同时观察历史 Outbox、退款恢复和结算对账指标。普通状态接口中 `provider_available` 只表示凭证已配置，不表示第三方在线健康。


## M6.1 准入检查

本阶段新增生产启动拒绝、结算模拟执行限制和 14 项机器准入清单；三端业务流程沿用 M5.5，APK 仅更新交付版本。默认开发启动仍使用 local profile。结算模拟只在明确的开发配置下启用，生产配置永远不能调用模拟代付。

先安装 openapi/requirements-validation-lock.txt 中的校验依赖，执行 `python scripts/check-production-admission.py`。lint PASS 仅代表清单有效。执行 `python scripts/check-production-admission.py --release --commit <40位提交SHA>` 当前必须返回 BLOCKED/退出码 2。

可运行 `python scripts/check-production-startup.py --jar release/pawday-backend.jar --report backend/target/readiness-evidence/production-startup.json`，实际启动 JAR 验证 production、local+production、prod 别名和 deployment-mode 四种配置在 DB/HTTP 启动前被拒绝。报告 PASS 代表拒绝边界符合预期，`production_ready=false`。

正式供应商、主体资质、首发城市/来源与云端验收均未准备；不应将此包部署成生产服务。完整事实、适配契约和下一批依赖见 `docs/M6.1-生产准入与适配契约.md`。现有开发 Compose 和 .env.local 不可充当生产模板。
