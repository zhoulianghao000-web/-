## 实现与证据

- PostgreSQL 17真实连续WAL归档：不可覆盖归档脚本、失败可见和恢复补齐；归档失败时业务提交仍成功。在线pg_basebackup期间实际提交业务写入，原生pg_verifybackup通过。归档捕获后冻结合成源库以保证演练清单不再变化。
- 新建隔离卷恢复到数据库记录的时间点，真实暂停WAL回放并核对全部public表：包含之前的正确事实，排除之后的错误价格、库存和额外账本项。恢复暂停时写操作拒绝；另一个不可达的未来时间点真实失败且不提升。缺失/损坏WAL在创建目标之前拒绝。
- 恢复目标无公开端口、仅内部网络，默认只读；只提升本次随机标签的合成目标用于离线核对。应用启动增加recovery/restore/quarantine硬拒绝，实际JAR在数据库/Flyway/HTTP启动前退出。没有恢复应用或外部worker自动启动/解封入口。
- 使用独立于物理备份、单独HMAC认证且绑定集群/备份/最新水位的删除撤权登记。白名单回放三类记录：AI会话删除、个性化撤权、媒体删除；同时清除过期AI密文、失效提案和旧会话。较旧但签名正确的登记拒绝，重复回放事实相同。仅恢复READY且hash相符的媒体，被删除资源不复活。
- 从恢复后的商品事实调用既有BusinessSearchProjection和全量重建器。真实停OpenSearch后保留旧alias及持久重试，恢复后建新索引、原子切换alias；下架SKU不可搜索。没有用搜索备份代替PostgreSQL事实。
- 账本不可覆盖、inbox去重、价格/库存/支付/退款/结算/额度事实保持；待发送短信Outbox始终PENDING，没有重放外部业务副作用。备份/WAL/对象/历史key保留引用只能生成审核计划，禁止自动清理仍被引用的链。
- 无新增业务页面或运行时API，仍303个操作；V001–V020字节保持不变。

首轮本地及CI发现目标数据库尚未就绪时查询导致等待提前退出，已改为等待成功连接及暂停状态，并保存目标数据库日志；第二轮CI又发现Linux复制出的WAL私有权限与host UID不匹配，改为复制到独立目标卷并恢复postgres所有权，原备份不变且无须扩大公共权限。第三轮CI前20项恢复通过，最后源库重启后的核对也发现启动竞态，补齐成功连接与非恢复状态等待后继续保留全表hash精确相等要求。本地真实链路通过，最终完整CI通过。另发现既有自动搜索集成测试只等待APPLIED，bootstrap可能早于Rabbit消费完成；改为在原15秒上限内同时等待APPLIED/PUBLISHED/PROCESSED三项事实，保留精确价格断言及真实服务。三次恢复失败和一次后端集成失败的日志/artifact均保留，没有放宽真实恢复、失败拒绝或搜索故障要求。
