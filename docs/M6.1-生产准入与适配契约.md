| 能力 | 仓库事实 | 正式接入缺口 |

| OTP 短信 | Outbox 同事务 + 稳定 challengeId；本地文件适配器 | 正式签名/模板/资质；生产 SDK；供应商回执、查询及不确定结果恢复；现有 void 接口不足以声称回执集成 |
| 媒体 | ObjectStorageProvider、本地对象、受控 key/凭证/引用 | 正式存储、私有权限、内容检测/转码/CDN、生命周期及物理删除；无云适配器 |
| AI | 官方 HTTPS DeepSeek 适配器、证据选择、额度、加密/清除 | 无密钥、云端效果/费用/限流/真实隐私验证；HTTP 故障 fixture 不计入云端推理 |

| 身份/运维 | 三套身份、RBAC、一次性 reverify、审计；真实 CI 四服务 | 正式员工开户/MFA 丢失恢复、最小权限基础设施/TLS、Secret 版本轮换、告警送达 |

外部条件以“未准备/未验收”存储。当前没有创建任何真实商户、订单付款、短信发送、云资源或部署。不要在聊天、仓库、交付报告或 App 中填写密钥、证书私钥、手机号清单及完整银行资料。

## 生产拒绝与模拟结算修正

`ProductionAdmissionGuard` 作为 Spring EnvironmentPostProcessor，在配置加载后、连接池/Flyway/HTTP server 之前运行。生产 profile（包括 prod、大小写误用）或 `PAWDAY_DEPLOYMENT_MODE=production` 明确拒绝启动，原因标识为 `PAWDAY_PRODUCTION_ADMISSION_BLOCKED`。生产真实支付/退款、短信、对象存储和代付尚未实现，这是代码级锁，不能通过 `production-ready=true`、混入 local 或模拟开关绕过。拒绝输出只含固定原因 ID，不打印配置值。

结算模拟新增 `pawday.settlement.simulation-enabled`，默认 false，仅明确开发配置启用；local profile 自动启用。production/prod 或 production deployment-mode 始终禁用。initiate/retry 在消耗 reverify、创建结算、写账本之前返回 503；worker 不再扫描执行模拟代付。已有账本、冻结金额、退款冲正及受控权限保持原事实。本阶段不将事务内模拟逻辑接到外部 SDK。后续真实代付必须按下文事务契约重构后验收。

默认 development/staging 只允许工程运行，不提供生产许可。Compose 继续仅用于 loopback 开发；不要将其默认密码、无鉴权 Redis/OpenSearch 或端口映射复制到生产。后续生产模板必须使用独立账号、TLS 身份验证与网络限制。

## 机器清单和证据契约

`deployment/production-admission.json` 及 JSON Schema 是正式盘点。14 个必需 gate 不可删减或重复；每个 gate 绑定代码事实、必需场景、状态、阻塞和证据引用。当前 14 项全部 PENDING。Secret 只可记录 `secrets://pawday/production/<name>` 这种引用标识，不能填真实值。

| sms | 模板批准、稳定键、模糊回执、Outbox 恢复 |
| storage_media | 私有读写删、MIME/hash/大小、过期凭证、保留删除 |
| ai_live | 真实推理、证据边界、失败额度释放、费用/限流 |
| logistics_navigation | 真实轨迹、实体高德交接、定位拒绝、不隐式收货 |
| operator_mfa | 正式开户、一次性再次验证、越权、MFA 丢失恢复 |
| privacy_delete | 归属、保留决策、对象引用清理、备份恢复后重放删除 |

执行：

```powershell
python -m pip install -r openapi/requirements-validation-lock.txt
python scripts/check-production-admission.py --report backend/target/readiness-evidence/inventory-lint.json
python scripts/check-production-admission.py --release --commit <待发布的40位提交SHA> --evidence-root deployment/production-evidence --report backend/target/readiness-evidence/release-blocked.json
```

lint PASS 表示清单结构与代码引用有效，`production_ready=false`。release 当前必须返回 BLOCKED/退出码 2：14 项真实证据缺失和代码适配器锁。无效输入/伪 VERIFIED/必需场景减项返回 FAIL/退出码 1。禁止把 BLOCKED 流程当作上线通过。未来即使人工造出全 PASS 文本，也不能解除当前 runtime 锁；后续阶段须实现适配器并修改受测代码。

## 适配契约：支付、退款和代付

1. 冻结业务指令先在 PG 提交，后进行服务端渠道调用，再以短事务核对原指令/金额/CNY/商户/应用/租约和渠道结果，追加 receipt/ledger/outbox/audit。禁止在持锁事务中调用支付、退款或代付 SDK。
2. 支付绑定 attempt_no；退款绑定 refund_no 和已收款渠道 transaction；代付绑定 settlement_no 与冻结收款账户引用。相同键和指令重试只查询/恢复原渠道动作；请求键复用但参数变化须拒绝。
3. 超时、5xx、断网、正文失败或 ack 丢失属于 UNKNOWN，不当作未扣款/未退款，不换新键盲重试。不确定查询必须先于重发；有限退避、人工受控恢复，不静默改账。渠道最终失败与暂态失败分离。
4. 回调按原始 body、时间戳/nonce、证书序列/公钥执行真实性校验，限制时效/重放，并核验商户/应用/币种/金额/交易归属。只有可信回调可以入 durable inbox；HTTP 成功确认必须晚于事务提交。重复通知必须与主动查询汇合到同一个幂等领域处理。现有 bearer 路由不等于渠道验签入口，新回调路径必须单独落实权限边界，不能放宽全部 public 路由。
5. 当前 PaymentGateway.Result 缺少真实 App 调起 payload，暂无回调验签/inbox 协议及渠道证书管理；后续须版本化补齐 DTO/OpenAPI/客户端，而非把模拟 transaction ID 当作正式支付 token。
6. 代付必须新增 provider 请求/查询/结果契约及 durable lease，将当前 attemptDisburse 的模拟事务拆开；崩溃恢复要覆盖“渠道成功、结果落库前退出”。结算事实只在核验支付成功后追加 SETTLEMENT_DEBIT，一次写账、不可覆盖、不重复代付。
7. 正式渠道是否支持跨商户拆分、延后结算、部分退款和已结算追偿须由主体/产品权限确认。尚未选供应商，不假设平台拥有任意托管或代付能力。

官方参考（2026-10-09 核对，接入时再核对所选产品版本）：[微信支付 APP 回调验签](https://pay.wechatpay.cn/doc/v3/merchant/4013070368)、[微信退款不确定结果与原单重试](https://pay.wechatpay.cn/doc/v3/merchant/4014959631)。这些资料用于约束适配设计，不代表已开通渠道。

## 适配契约：短信、存储、AI 和导航

短信继续创建 OTP+Outbox 同事务。challengeId 为稳定发送键；正式适配器需返回供应商 receipt/明确不确定结果，并提供查询或可核实的幂等保证。现有 SmsGateway.send void 可保留开发实现，真实回执持久化/查询须新增版本化契约，不通过更换键重发规避限流。发送成功也不能让已到期/已消费 OTP 再有效。

对象 key 由服务端 owner/scope 生成，业务表只存 media_asset 引用；上传授权限定 MIME、size、hash、TTL、一次消费和对象 key，不能让客户端选择任意 bucket。真实适配器必须实现元数据、私有 read、幂等 delete、失败恢复。需要对象扫描/转码时设独立状态，未验收不得称媒体安全检测已完成。当前历史引用阻止直接删除，应先完成保留/撤权策略，禁止强删订单/审核证据。

DeepSeek 保留 M5.5 的官方主机、时限/大小、证据白名单、无交易工具、事务额度和加密/清除边界；真实账号仅通过服务端 Secret 注入。云端推理及模型费用/限流至少记录脱敏请求关联、响应/拒绝、耗时和计费统计，不记录原始问题。现有边界自测不是模型效果。官方参考：[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)。

物流 UNKNOWN 必须保留，不生成虚构扫描；跟踪不自动确认收货。高德继续使用已公开门店的 HTTPS 目的地交接，用户前台明确授权定位；首发实测 Android/iOS 安装、未安装、拒绝和服务关闭分支。没有选择新增 SDK/POI 服务时不增加无用凭证需求。

## Secret、监控、隐私与恢复契约

生产使用独立 Secret 管理，环境变量/挂载文件由部署系统注入；禁止提交 .env、私钥、明文 OTP、refresh token、银行资料。当前 PAWDAY_AUTH_SECRET 同时参与加密/HMAC，不得在旧数据库上重新生成；轮换需 key_id、双读/单写和历史密文迁移及回退测试，不能直接替换后期待旧数据仍可读。正式员工用最小 scope/RBAC 开户，管理员 TOTP 与恢复流程须经独立受控验证。

已有 Outbox backlog/oldest-age、PENDING/PUBLISHING/FAILED_RETRYABLE/DEAD、inbox/SMS DEAD，以及 AI 三态/expired-lease 指标是事实。支付 UNKNOWN、退款租约/滞留、结算差异、通道耗时与云端费用告警仍需补齐并验证实际送达；当前不声称已有 Prometheus/Alertmanager 生产部署。采集管理接口保持 RBAC/内网限制，不为监控方便公开凭证/数据库详情。

备份同时覆盖 PG 基础备份+WAL、对象元数据/本体、加密密钥版本和恢复脚本；搜索是派生数据，用新索引重建与原子 alias 切换，不能仅恢复搜索索引替代 PG。恢复到隔离环境，先禁外部副作用 worker，核对已收款/退款/代付事实、Outbox/inbox 去重与渠道查询后受控恢复；不得在未知渠道结果上重放新付款。按正式负载和业务损失预算确认 RPO/RTO，再记录实际演练值，当前不虚构“已达标”。[PostgreSQL 17 PITR 官方文档](https://www.postgresql.org/docs/17/continuous-archiving.html)明确描述基础备份/WAL 与时间点恢复机制；本阶段仅冻结演练契约，未执行生产恢复。

账号删除要区分授权撤回、脱敏、引用解绑、对象物理删除、交易/审计保留与备份过期。先确定运营及适用保留规则，再实现受控任务/失败重试/可追踪删除收据；不可覆盖交易证据不能被级联删掉。恢复备份后应重放删除/撤权墓碑，防止已删除私有内容重新公开。

## 后续顺序

M6.1 以盘点和工程拒绝门禁验收，生产仍 BLOCKED。下一步 M6.2：用户准备所选主体/供应商与应用权限的非敏感清单后，先实现正式支付/退款/结算适配、回调与不确定恢复；并行的独立工程项可先补生产指标/告警接线和隔离恢复脚本。之后按准入清单逐项完成短信/存储/AI、正式员工/隐私、实体设备/首发资料/恢复容量。各批继续开发包、验收报告和计划同步；所有生产 gate 真实通过且负责人批准后才可上线。
