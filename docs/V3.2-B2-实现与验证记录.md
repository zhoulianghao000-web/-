## 首轮实现及失败留痕
- V037 新增三类业务事实（投递、租约尝试、观察回执），另增加独立合成渠道幂等存储 integration_delivery_fixture_orders。第四表用于真实模拟“渠道已创建但业务回写失败/进程丢失”的持久恢复，不能拿本地业务回执充当渠道查询结果；不存地址、姓名、电话、URL、凭证。并非真实供应器。
- 声明按原订单→子订单/支付→连接→映射→排序 offer/余额→订单行；原取消、售后批准/检收/平台裁决、手工发货在原锁链下先查同一责任。退款/返库/发货触发器提供额外守护，不在库存日志后倒锁连接。
- READY 起保留整个子订单的原生自动处理保护；多连接只冻结本连接的活动映射行，保护取整个子订单的所有声明并集。仅匹配且证明未创建的 REJECTED 可解除；ACCEPTED 投递结果已知但 fulfillment_hold_open=true。暂停可阻止新外发，旧固定号查询及责任保留。
- 首轮 13 项（12 个新 HTTP 案例及升级）有三项夹具失败：同一商家/门店/商品在循环内重复创建报价，被原 OFFER_ALREADY_EXISTS 正确拒绝两次；跨商家夹具未授新权限，被权限层正确拒绝 403，而预期跨范围 404。拆开循环数据归属、为外店仅补受测集成权限后复验通过；业务授权门槛未放宽。日志 .maintenance/v32-b2-first-tests.log 保留。
- 第二轮原 12 新案例、升级 1、策略 6 共 19 通过（本地阶段结果，非最终数）。后续增加真实 HTTP 取消竞争、租约接管/旧令牌、渠道成功后审计回滚恢复、售后与退役保护、客户端非法载荷和事实防篡改；待新一轮结果，不把测试不同版本相加。
- 初次新契约收集仍沿用原商品夹具采集分派，把商品请求写入 B2 样本，校验器按 unmapped 拒绝；现只收实际 order-deliveries 请求，历史校验器不放宽。
- 运行契约只增三项及明确的履约占用字段；B1 所有路径/结构保持。TS/Dart 已重新生成。实际 PG 元数据 188 个表/视图对象、1574 列，37 迁移；隐私覆盖已通过，仅覆盖复核，不批准留存政策或删除。
