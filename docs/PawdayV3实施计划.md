已检索当前工程、项目计划根目录及历史阶段快照，并核对原始 V1 PRD 与原聊天的 V2 范围确认。现有明确版本计划只有 V1、V2；原始 PRD 明确将价格历史放入 V2，但没有单独定义 V3。商品标准资料的 V3/V4、OpenAPI v3 等字样不当作产品 V3 范围。

## 既有待办候选（尚未确定纳入 V3）

来源：[V1 原始需求收尾复核](V1-原始需求收尾复核.md)。下表保留原归属，不因规划 V3 改写为已完成，也不重复开发已有能力。

| 事项 | 已有事实 | 后续应核对的具体内容 |
|---|---|---|
| 首页与详情 | 已有宠物、AI、知识、商品和报价入口 | 首页额度/券/附近快捷入口、商家等级展示、详情层次与既有参考设计的一致性 |
| 优惠和运营配置 | 已有交易、会员、积分、优惠基础 | 创建/领取/停用、商家参与、平台配置、权限、幂等、审计及结账分摊闭环 |
| 轻量推荐 | 类别浏览、确定性宠物适配、依据解释可用 | 收藏/浏览规则推荐、关闭个性化后的行为、冷启动和信息不足，不默认引入复杂模型 |
| 运营预警、推广与风控 | 已有发货、权限、审计和交易守恒门禁 | 超时预警、推广标识、异常规则的实际覆盖，不能用权限隔离代替完整业务验证 |
| 附近与定位 | 已有列表、城市/模拟定位、公开门店和导航交接 | 地图模式、设备定位及正式渠道证据；既有手机操作限制仍适用 |
| 账号与隐私 | 已有会话、RBAC、二次验证、AI 偏好与清理 | 微信、注销/匿名化、保留政策及跨域删除需独立范围和有效依据，不编造政策或材料 |

AI 客服、ERP/WMS、电子面单、自动订粮、付费预约、社区、高级 BI、复杂推荐等，仅在原始需求中作为未来/暂缓事项出现。它们没有已确认的 V3 排期，不据“最后 V3”一句指令全部加入本轮。宠物小游戏维持原需求永久排除。
