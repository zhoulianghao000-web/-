# M4.4 子订单履约

基线：PR #9 合并后的 `cf5f51347f74319cd7e6e97653b38fd7d8ff048a`。运行时契约 `openapi/pawday-m4.4.yaml`，共享 TypeScript/Dart DTO 从该契约生成。Flyway V012，JAR 0.4.4。

商家持 `order.read`、`order.ship`，且拥有子单所有订单项的 merchant/store scope 后，可以按订单项和数量创建包裹。`If-Match` 为子单版本；`Idempotency-Key` 重试原命令，同键不同参数拒绝。未付款/取消/全部发货后拒绝新包裹。物流编码与运单有字符/长度校验，已使用的公司/运单组合不可重复登记。商家发货界面允许剩余数量分包。

`shipments`、`shipment_items`、`shipment_receipts` 是不可覆盖的 PostgreSQL 数量事实。订单项归属以组合外键校验；持父单→子单→订单项锁防止并发超发，数据库触发器约束累计数量和付款事实，延迟约束确保包裹非空、履约事实与状态共同提交。数量不再次扣库存，不修改价格/地址/优惠快照。库存扣减仍仅由支付确认完成。

消费者只能明确确认自己的子单中选定包裹，不能默认确认其他包裹或商家。逐包凭据唯一、可幂等重试。部分收货为 PARTIALLY_COMPLETED，全部有效数量收货为 COMPLETED。子单状态根据发货/收货数量推导；父单对外展示状态由全部子单派生（部分发货、待收货、部分完成、已完成），父单存储 FULFILLING 为交易生命周期，版本随履约事实推进。收货不创建结算账本，本阶段只发出后续使用的可靠事实。

每次发货/收货同事务写入事实、子单状态/版本、父单版本、审计、Outbox 与幂等结果；RabbitMQ 不可用不阻断事实提交，Publisher Confirm 后标 PUBLISHED。ShipmentCreated/SuborderReceiptConfirmed 持久绑定 order.facts，后续结算消费者沿用 inbox 去重，本阶段尚无结算副作用。

商家基本订单读取不增加收件信息。独立履约 GET 仅对已付款且未完成、具有发货权限及完整范围的商家展示冻结配送地址；读者/平台履约端点不提供地址。命令缓存不保存收件信息，审计和 MQ payload 仅包含业务引用与版本。三端在退出/账号变化后丢弃私有晚到响应。

LogisticsProvider 保留服务端适配边界。当前供应商未选择，实际适配器如实返回 UNKNOWN、stale、空轨迹，不编造签收；轨迹与用户收货分开。已发包裹不可直接改运单，受控纠错命令留待后续物流运营批次，不能旁路修改事实。电子面单、真实物流 SDK、自动收货、已付款部分取消/退款、售后、积分及结算均不属于本批实现。

启动：开发包解压后配置 `.env.local`，启动 Docker Compose 四服务，执行 `scripts/start-local.ps1` 加载 `release/pawday-backend-0.4.4.jar`；Vue/Flutter 启动方式沿用根 README。演示商家 `local-staff-a` 只拥有自身门店范围，所有演示凭证由环境显式指定。

门禁：后端身份/订单/支付回归 + 履约越权/范围/部分发货/显式收货/并发/回滚/不可覆盖验证；真实 PostgreSQL/RabbitMQ/Redis/OpenSearch 集成；实际 HTTP 契约；Web lint/typecheck/test/build、Flutter analyze/test/web/APK、生成一致性、真实浏览器和 Dart HTTP。本机无 Docker，真实门禁在 CI，不改用 mock 替代。
