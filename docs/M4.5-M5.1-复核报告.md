## 缺陷与修正

| 项目 | 原问题 | 修正 |
|---|---|---|
| RabbitMQ 路由 | M4.5–M5.1 的 18 类业务事件无绑定；mandatory 发布会被退回 | 持久 quorum 业务事实队列，显式绑定全部事件；真实 broker confirm 门禁 |
| 退款并发与恢复 | 无租约，多 worker 重复调用；晚响应可能覆盖新尝试 | V016 增加 token/lease，SKIP LOCKED 抢占，token fencing；恢复先查询固定退款号 |
| 重试与人工恢复 | UNKNOWN 无限自动重试；FAILED_FINAL 无受控恢复路径 | 8 次转人工；既有管理员 payment.requery 经 RBAC、reverify、幂等、审计恢复原退款号 |
| 优惠守恒 | FAILED_FINAL 被排除在未完成退款之外，可能提前返券 | 所有非成功/非取消退款均阻止返券 |
| 结算后第二次退款 | track 从 SETTLED 变 ADJUSTED 后误当未结算，后续抵扣丢失 | 以 settlement_id 为已结算事实，逐次桥接后续结算 |
| 佣金尾差 | 每笔退款单独取整，完整分笔退款不能全额冲回佣金 | 累计成功冻结单位额度计算目标冲回量，减已有不可改写账目 |
| 结算并发 | 选择账目后才锁 track，售后冻结可能被绕过 | 选择前按固定顺序锁 track，等待后重查资格 |
| 计划/兑换退休 | 查旧 ACTIVE 版本仍可购买或兑换 | 最新版本为唯一权威，退休或旧 ID 拒绝；发布/购买共用每 code 锁 |
| 购物积分 | 减原始运费导致运费优惠少发积分 | 商品项实付总和为积分基数 |
| 积分退款 | 每笔 floor 使分笔退款留有多余积分，账户锁不统一 | 累计成功商品退款计算追回目标，所有余额写入使用账户锁 |
| 配置与续费并发 | 政策版本可重复；首次双会员激活插入竞争 | 政策唯一版本约束、版本分配锁、首单激活锁用户行 |
| 签到与输入 | UTC 日界；AI quota int 溢出；benefits 元素/手工积分范围缺校验 | 上海业务日期；类型与范围按契约校验 |
| 配置缺失 | 无积分政策时支付成功且静默不发积分 | 明确 503，业务事务保留待确认，配置恢复后查询渠道收款并完成权益 |

V013–V015 已发布迁移不修改；变更仅新增 V016。退款租约字段为内部数据，不暴露给客户端，既有 OpenAPI DTO 保持一致。手工积分、购物积分和退款追回的 PointsChanged 与账目同事务写 Outbox。
