# M6.5 跨域隐私与恢复接入盘点

2026-10-11。从 PR #22 合并主分支 e4a4eb2f5337d960948cd4142aaa1861b3c21c5d 开始。范围：可机器复核的数据结构覆盖、账号注销缺口及恢复重新接入拒绝门禁。正式保留政策、生产主体及供应商条件尚未准备；本阶段不提供账号删除或恢复解封命令。

## 数据边界与保留决策

`deployment/privacy/data-inventory.json` 覆盖 V001–V021 实际创建的 145 张业务表、1,155 个字段、19 个领域；绑定全部迁移 SHA256 和真实 PostgreSQL 字段名、顺序、类型、可空性、字符长度的规范化摘要。排除 Flyway 自身历史表及隔离演练专用 m63_fixture；这些排除不适用于其他表。新增表、字段、类型变化、遗漏列或新增迁移都必须重新审查。结构覆盖不等于逐字段完成法律分类；JSON 内嵌属性、业务链和外部副本仍须逐项审查。

| 领域及敏感面 | 现有事实与注销缺口 | 下一步决策 |
| --- | --- | --- |
| 身份、OTP、会话、商家/管理员权限 | app_user 与 identity_principal 是不同主键体系；手机号、凭证、refresh、二次验证和角色范围分散，不能只设置 deleted_at | 确认账号关联、重新注册、商户责任转移、在途操作与全端撤权协议 |
| 宠物及购物上下文 | 宠物、体重、过敏原、购物车、地址、Quote 和订单快照有直接引用及 JSON 副本 | 逐项确认匿名化、解绑、清除范围，防止历史快照泄漏 |
| 订单、支付、退款、履约、结算、会员积分 | 交易金额、冻结单位、权益与不可覆盖账本必须守恒；订单地址、物流、售后证据另含个人信息 | 分离经济事实与个人字段；明确保留依据、期限及争议/冻结优先级，不能级联删账 |
| 评价与文章 | review_revisions 不可变，含正文、媒体、宠物标签；发布版本和审核历史独立 | 确认撤回/遮盖层、历史可见性及不可变存储处理，不绕过触发器 |
| 客服与通知 | conversation_messages 不可变，含正文、附件和订单卡片；consumer_id 引用 principal，通知另有接收方 | 确认参与者权利、争议保留、正文遮盖与卡片授权；关闭会话不等于删除 |
| AI | 已有清除、过期、撤权和独立 tombstone；请求、额度、已接受宠物事实有不同生命周期 | 区分正文清除、个性化撤回与既有事实；完整注销方案须单独定义 |
| 媒体、商品、附近、搜索 | 媒体引用计数阻止在用对象直接删除；搜索是派生数据；门店联系人和来源资料也需要审查 | 同步处理对象版本、引用、公开索引及商家主体关系 |
| 审计、Outbox/inbox、隐私登记 | actor/object、幂等响应、消息载荷可能携带引用；登记用于防止备份复活，不能随主体一并抹掉 | 确认最小化与保留依据；不删除去重事实后直接重放外部动作 |

19 个领域保留决策全部 `PENDING`，依据和天数均为 null，未编造法定期限。交易/履约/资金/权益、投递与隐私事实被标记为保留事实并审查个人字段；其他领域仍需审查。业务期限和过期字段不是正式法律依据。最终生产决定需要主体提供经确认的政策及可审计证据。

另外明确七类数据库外表面：对象历史版本、搜索索引、RabbitMQ 消息、Redis 身份缓存、应用/审计日志、备份/WAL/历史密钥、外部供应商。均待审查，不把“库内清除”当成全链路清除。恢复链仍受 pin 保护；盘点工具不清理备份或密钥。

## 工程门禁

Java 使用真实 Embedded PostgreSQL 执行全部迁移，以 REPEATABLE READ / READ ONLY 事务只读取 information_schema；实际 UPDATE 被数据库拒绝。Python 检查真实元数据与冻结清单、迁移和领域决策完整性。CI 明确运行该步骤，遗漏 schema 文件或检查失败直接失败。报告仅含表/列数量、结构摘要、领域计数和待确认数量，不导出个人值。`PASS` 仅表示结构覆盖通过，`account_deletion_ready`、`deletion_authorized`、`production_ready` 恒为 false。

真实 PITR 演练在同一只读快照中提取恢复登记及待发事件/会话计数，以已独立验签且验证最新 pin 的登记进行比对。序号、动作、主体和事件时间必须一致；等价时区归一化，不能因为时间表示格式不同误报分叉。离线回放生成的本地事实时间与原独立事实不同，属于分叉，不能启动 exporter 覆盖原链。缺尾、来源不匹配、序号空洞、待发 Outbox 或尚活跃旧会话都进入拒绝路径。

重新接入报告输出固定原因及数量，不输出主体、消息、手机号或对象正文。核对前后全表事实摘要必须一致。即使登记完全匹配，仍明确拒绝解除隔离，因为恢复接入协议、正式保留政策、外部副作用核对和生产准入尚未具备。它是复核资料，不能作为恢复签批。

## 尚未完成的协议

恢复重新接入至少还需要可信独立最新水位托管、登记 epoch/来源接续协议、原时间事实的受控处理、Outbox 与 broker/inbox 的恢复边界，以及支付/退款/出账/短信供应商逐项对账。不能直接复制独立登记进不可变表、禁用触发器或启动全部 worker 来“补齐”。账号注销还需冻结申请、全端撤权、在途交易/争议处理、跨域遮盖和重试、可证明的外部清除等设计与实际验收。当前工具既不修改事实，也不返回 SQL 执行计划。
