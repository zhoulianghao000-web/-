# Pawday M6.4 开发交付启动说明

本阶段交付版本 0.6.4，Android debug 0.6.4+10。仅用于开发/工程验收；生产准入仍 BLOCKED，M6 总验收未关闭。

开发包保留完整源码、`release/pawday-backend.jar`、商家/管理员 Web 构建与启动脚本。沿用仓库 README 的 Java 21、PostgreSQL、Redis、RabbitMQ、OpenSearch 和三端启动步骤；执行迁移至 V021。原 V001–V020 不修改，已有数据库由 Flyway 正常增量升级。源码包无需提供密钥，正式供应商凭证均未包含。

## 可选的独立开发导出

登记触发器始终生效。默认 `PAWDAY_PRIVACY_EXPORT_ENABLED=false`，未配置导出时指标如实显示未覆盖与水位年龄。需要验收本地 exporter 时设置：

| 环境变量 | 含义 |
| --- | --- |
| PAWDAY_PRIVACY_EXPORT_ENABLED | true，仅在独立目录与签名密钥准备完毕后开启 |
| PAWDAY_PRIVACY_EXPORT_ROOT | 服务账号独占的绝对目录，与媒体根目录分离；不位于 PostgreSQL 数据目录 |
| PAWDAY_PRIVACY_EXPORT_SIGNING_KEY | 独立生成、至少 32 字节的 Base64 签名密钥；不复用登录/数据加密密钥，不写入仓库、日志或交付包 |

应用账号需读取 `pg_control_system()` 的数据库来源标识；正式最小权限部署需按供应商核验。导出根目录的 `latest.json` 和不可覆盖 checkpoint 含隐私主体引用，只供受控恢复审查，不做静态站点发布、不上传普通 CI artifact。独立目录的本地适配器不能代替生产异地存储或可信最新水位托管。

## 工程门禁

GitHub Actions 保留三端、OpenAPI 再生成、真实四服务、运维和恢复七个 Job。后端新增 `PrivacyJournalTests`，现有 AI/媒体 HTTP 测试增加事务登记与审计失败回滚；Python 新增独立导出验证测试。恢复 gate 仍只允许带固定标签的合成源和新建内部网络目标，无任意生产地址参数。

本地可运行 Maven 测试及 `python -m unittest discover -s scripts/tests -v`。物理恢复 gate 要求干净受测 Git tree、真实 Docker/四服务相应工程栈及新建私有 `.local-recovery`；该目录含备份与主体引用，不能交付或覆盖旧阶段证据。正常开发启动绝不应使用 recovery/restore profile；实际 JAR 会在数据库、Flyway、HTTP 前拒绝恢复应用启动。

恢复必须先获得备份之外的可信最新 checkpoint pin、最小序号和必要截止时间。签名正确但陈旧/缺尾的导出一律拒绝；通过离线清除与搜索校验后也不会自动解除隔离。恢复生产登记链、账号注销、完整法定保留政策、独立水位托管、供应商与设备/容量验收仍待后续阶段。
