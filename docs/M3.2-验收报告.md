## 基线与交付范围

M3.1 PR #3 已按用户授权合并，合并提交 `8367c275e22c7c7a6939e250497074d56c838517`。本批从该主分支创建 `codex/pawday-m3.2`，不存在基于旧 M2 代码开发的问题。

实现品牌、SPU、SKU，带来源的配料/营养/过敏原/适用阶段资料版本，草稿和显式发布，所属商户内的纠错申请、平台批准/驳回、审核记录，CSV/XLSX 文件解析、逐行校验预览及原子确认/取消。管理员和商家 `/catalog` 页面使用生成客户端接通实际 API。

历史已发布资料及其过敏原在 PostgreSQL trigger 层禁止覆盖、删除或迁移到其他草稿；新发布保留旧资料并退休旧版本。营养保留单位、基准及标示上下界；未知过敏情况与明确无标注过敏原分开。全部资料保留来源、更新日期、版本及发布者，不推断缺失资料，也不导入真实商品种子。

平台写入检查 ADMIN realm + RBAC；敏感动作消耗当前会话、指定 action 的一次性 reverify。商家不能直接改平台标准，也不能读取草稿；纠错身份和 merchant scope 来自服务端当前主体，外商户请求返回 404。SKU 基线变化时，旧纠错/旧导入预览返回 409；审核不能重复执行或静默改判。

共享 PostgreSQL 幂等执行器以 actor/action/key 序列化命令，规范化 payload 哈希；重复相同请求返回原结果，改变 payload 拒绝。事务包含业务资料、审核/导入、审计、Outbox 和幂等结果，失败恢复二次验证证明并全部回滚。发布写入 `CatalogStandardPublished`，经 broker confirm 进入持久 quorum 队列 pawday.catalog.standard-published，保留待后续商品投影使用的版本引用；M3.4 接入消费者前无 TTL、不消费。

导入只支持已有 SKU 资料版本，不猜测身份或覆盖基础商品。单工作表、两个固定字段、每批 200 行/2 MB、展开 8 MB；拒绝公式、宏、外部链接、DTD、路径穿越、重复、未知 SKU 和错误资料。确认前不变更事实；任意一行失败全批回滚，可查询或取消恢复。

## 边界与下一步

没有首发商品真实来源或授权数据；来源真实性需运营审核，本批验证结构、权限、版本和事务，不声称自动验证标签事实。新品建档由平台完成；本批商家申请范围为既有 SKU 纠错。导入是有限批量的同步预览，不包括任意 Excel 列布局、复杂宏或大规模异步导入。
