## 已交付能力

- 消费者发起平台/门店人工会话，重复创建返回同一个会话；关闭和重新打开使用版本检查。商家不能任意向用户营销发信。员工只读当前 realm/merchant/store 队列元数据；消息、附件、卡片只开放给消费者及当前分配客服。
- 领取/转接需 support.assign、If-Match、幂等、一次性 reverify 与同事务 audit。目标必须当前有效且具备读/回复权限及同一商家门店授权；转接后旧客服失去历史、图片和重复命令的访问权。平台与商家会话隔离，聊天不会授予订单读取权限。
- 不可覆盖消息事实，文字/图片/商品/子订单卡片。会话行锁分配递增序号；命令、消息、媒体引用、Outbox 同事务。相同键重试返回原消息，改正文复用键冲突；并发发送不重复序号。正文纯文本渲染，Outbox 只包含事实引用和序号。
- 三端增量读取、断线恢复、失败保留内容与幂等键；已读游标只前进，不能超过现存序号，自己的消息不计未读。有界等待逐次重查会话/权限/参与方，不持有数据库事务或连接。传输确认只表示服务器 inbox 持久化，已读为独立游标。
- CHAT 凭证上传 PNG/JPEG，单文件 5 MiB、每条最多 4 个资源。服务端验证真实内容、类型、大小和凭证时效；数据库只存引用。私有读取需要当前参与方，响应 private/no-store/nosniff；转接/身份/门店变化及迟到响应隔离。引用后附件不得删除。
- 商品卡片打开时检查当前商品/标准/报价；下架或退休返回不可用。子订单卡片核验消费者归属及当前员工订单权限，门店范围按订单项检查；混合门店子订单不越权。
- 七类独立偏好：订单、售后、降价、到货、吃粮、活动、客服。默认开启，关闭某类不影响其他类；历史消息继续可读，notify_enabled 冻结生成时偏好。接通订单/履约、售后与客服的真实事实生产者，跳转目标重查归属。其他类别生产者随对应业务接入，OS 生产推送未接入。
- RabbitMQ quorum queue + confirm；support-notifications-v1 inbox 按 consumer/event_id 去重，业务提交后 ack。消息交付游标只跨越连续完成的序号，乱序不误报已交付。有限重试、DEAD/DLQ 和受控重放；真实 broker 停机时 HTTP 业务仍提交，恢复后补偿。
- V018 新增持久化模型，V001–V017 未改写；OpenAPI 3.1 共 272 个操作，本批 33 个新操作，TS/Dart 生成一致性通过。保留未来 SupportAssistant 接口，本批仅人工客服。
