# M2.2 投递数据模型与状态机

V001/V002 保留，V003 扩展，应用资源与 database/migrations 的 SQL 必须逐字节一致。

| 数据 | 权威字段与约束 | 目的 |
| --- | --- | --- |
| outbox_event | status、attempt_count、available_at、claim_token、claimed_by、lease_expires_at、last_error_code/at、dead_at、generation | PostgreSQL 持久发布状态；available_at 为下次允许重试时间 |
| root_event_id / transport_kind | EVENT / RETRY / DEAD_LETTER | 根业务 ID 稳定，重试/死信转发有独立 transport ID |
| processed_event | PRIMARY KEY(consumer,event_id)，status/attempt_count/generation/payload_hash | 同一消费者与事件最多产生一次数据库业务结果；重复消息忽略 |
| sms_delivery | event_id UNIQUE、challenge_id UNIQUE、claim_token/lease、status/attempt_count | inbox 与发送任务原子提交；外部发送独立领取 |
| otp_challenge | delivery_secret_ciphertext | 短期加密发送材料，仅 Outbox 引用挑战 ID；发送完成/过期时清除 |
| outbox_replay_command | PRIMARY KEY(principal_id,idempotency_key)，payload_hash/generation | 重放命令幂等，和授权消费/审计同事务 |

Outbox 正式状态：PENDING → PUBLISHING → PUBLISHED；发布失败 PUBLISHING → FAILED_RETRYABLE → PUBLISHING；达到最大次数进入 DEAD。过期 lease 以 LEASE_EXPIRED 走同一失败路径。只有受控重放允许 DEAD → PENDING，新 generation 隔离旧投递。状态 CHECK 和 claim 字段 CHECK 防止非 PUBLISHING 残留有效 claim。

领取使用 SELECT ... FOR UPDATE SKIP LOCKED LIMIT 1，提交 claim 后不持锁发 MQ。mark PUBLISHED 要同时满足当前 claim token、PUBLISHING、lease 未过期；旧 worker 更新失败，重复发布由 inbox 去重兜底。单轮 publisher 最多 16 个，横向扩展 worker 共享数据库协调。

consumer 事务锁定 (consumer,event_id)，保存业务结果或有限次数的重试决定，再 ack。失败事件的 RETRY Outbox 与 inbox 状态同提交；发布此 RETRY 耗尽次数时将根 inbox 转为 DEAD，避免原根 PUBLISHED 却不可恢复。PUBLISHED 仅表示 broker 接收，不表示业务或短信已经完成。

默认每阶段最多 5 次，退避 min(60s,1s × 2^(attempt-1))。业务消费/SMS/PUBLISH 故障生成 DEAD_LETTER 元数据记录，确认投递到 DLQ 后标 PUBLISHED。DLQ 转发失败不会无限递归生成 DLQ，它自身留在 DEAD，可仅重放该转发记录。队列畸形 JSON 通过 quorum at-least-once dead lettering 保留在隔离 DLQ；修复发送方后再决定处理，不能作为普通业务根直接重放。

短信状态：PENDING → SENDING → DELIVERED / FAILED_RETRYABLE → DEAD，过期或被替代 OTP 进入 SKIPPED。网关调用不在 PostgreSQL 事务内。challenge ID 是外部幂等键；供应商成功但本地结果未知时须复用此键或查询结果。数据库任务唯一不能代替外部供应商幂等能力。

重放只接受根业务事件或 DEAD_LETTER 转发记录，要求 outbox.replay、会话/action 二次验证、reason_code、expected_generation、Idempotency-Key。已 PROCESSED 的 inbox 从不清除；只有 DEAD inbox/SMS 任务可重新排队。OTP 过期或已被替代返回 EVENT_EXPIRED。审计写失败，重放与二次验证消费全部回滚。

错误仅存稳定分类：BROKER_UNAVAILABLE、BROKER_NACK、UNROUTABLE_MESSAGE、CONFIRM_TIMEOUT、LEASE_EXPIRED、UNSUPPORTED_EVENT_VERSION、HANDLER_FAILURE、SMS_PROVIDER_UNAVAILABLE 等；不保存包含密钥或请求内容的原始供应商异常。
