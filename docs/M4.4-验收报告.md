## 实现与验证

- 商家凭 order.read/order.ship 和整个子单所有订单项的 merchant/store scope 分包发货。只能履约已经服务端确认付款的有效数量；累计发货不超过数量减取消数量。未知、取消、未付款、全部已发状态拒绝新包裹。同键重试返回原结果，同键不同参数拒绝，If-Match 拒绝过期版本。
- 不可覆盖 shipments/shipment_items/shipment_receipts 为事实源；组合外键校验订单项归属。父单→子单→订单项锁串行化同单动作，累计数量触发器阻止超发；延迟约束保证非空包裹和数量派生状态共同提交。测试覆盖并发两个发货请求一成一拒、跨项/跨消费者/跨商家访问、混合门店授权、非法输入、未付款/取消拒绝、DB 不可覆盖和审计失败后完整回滚。
- 用户逐包明确确认，凭据唯一且命令可幂等重试；只影响该子单选定包裹。2 件分 1+1 发货与分次收货数量守恒；跨商家一单先发一子单，父单部分发货；确认一子单后父单部分完成，另一个子单保持待履约。完整数量收到才完成。
- 对外父单状态从子单派生；存储 FULFILLING 为交易生命周期，履约推进父单版本。付款、价格/优惠/地址快照与已消费库存均不回写，发货/收货不再次扣库存。状态和资金事实分离，完成尚不等于结算到账。
- 发货/收货事实、子单状态/版本、父单版本、幂等结果、审计和 Outbox 同一 PostgreSQL 事务。ShipmentCreated/SuborderReceiptConfirmed 接入 durable quorum 订单事实队列。真实 RabbitMQ 网络中断时已付款订单可发货、事件留库并进入重试；恢复后 Publisher Confirm 确认发布。重复收货命令不再产生凭据或 Outbox，既有真实 MQ 幂等消费与确认丢失门禁继续通过。
- 商家基础订单接口未增加私人地址；独立履约 GET 仅对有发货权限、完整范围且已付款未完成的商家展示冻结配送地址。只读者/平台履约视图不展示地址，幂等缓存、事件和审计不保存收件明文。Web/Flutter 退出或账号变化后舍弃迟到私人响应。
- Vue 商家发货数量/运单、平台履约只读视图、Flutter 逐包物流/确认界面均接通。真实浏览器用真实 OTP/支付/发货接口创建业务，再从商家界面发货、平台查看收到事实；真实 Dart Repository 流程查询包裹、读取 UNKNOWN 轨迹、确认并同键重试收货，最后查看 COMPLETED 父单。
- LogisticsProvider 在服务端适配，当前供应商未选择，真实适配器返回 UNKNOWN、stale 和空轨迹，不编造扫描记录；物流签收不自动确认用户收货。
