# Pawday M3.1 宠物分类与档案

实施日期：2026-10-04。基线：M2.4 PR #2 已合并，主分支合并提交 `89793b3c30d8675e5de673dbedbd901af701195e`；开发分支 `codex/pawday-m3.1` 从该提交创建。

## 实现范围

- `V006` 建立分类、品种、过敏原、不可覆盖的生命周期规则版本、阶段定义、消费者宠物档案、过敏记录和体重时间序列。只内置五个父分类及 UNKNOWN 阶段，不植入未经审核的医学年龄数值或商品事实。
- 匿名 taxonomy/breeds/allergens 读取；消费者档案创建、分页查询、修改、软删除、体重记录。对象归属只从消费者身份取得，跨用户查询/修改/删除/体重访问统一拒绝。
- 修改、删除及体重新增要求带引号的 `If-Match`；写入要求稳定 `Idempotency-Key`。同一身份/命令/键使用 PostgreSQL 事务锁串行执行；请求字段顺序规范化，重复请求返回原结果，不重复写事实或审计；不同有效负载返回 409。
- 管理员分类/品种/过敏原新增、停用、年龄规则版本发布，受服务端 RBAC、会话和动作绑定的一次性二次验证及审计控制。发布规则保留旧版本；不允许重叠区间、混用单位或无来源的数值规则。停用词典项保留历史关联，现有档案仍能读取和维护。
- Flutter 真实 Repository/API、宠物列表/添加/编辑/删除、体重记录、当前宠物选择；退出、切换用户和删除当前档案清空 context。列表消费服务端分页，迟到的旧身份响应不能填回私有状态。
- 管理员 Web 新增宠物分类页面、词典项维护与年龄规则发布表单；保存需要密码和新的 TOTP，处理后清空凭据，查看入口和操作入口分别检查权限。
- `pawday-m3.1.yaml` 在已实现 M2 契约上加入 18 个宠物接口；TypeScript 与 Dart DTO/路由从该规范生成。CI 继续全部 M2 回归门禁，并验证宠物真实 HTTP 响应、管理员真实操作与真实 Dart 宠物流程。

## 生命周期规则

数值区间采用 `[min,max)`，日期使用 Asia/Shanghai。有可信生日时按历法计算完整天/月/年；没有生日、只有估算年龄、没有已发布可信规则或年龄未被区间覆盖均返回信息不足。当前实现不自动继承父分类年龄规则，动态鸟/水族/小宠不能误用猫狗阈值。已发布资料版本和阶段有数据库不可变保护；后续 SKU 适用阶段将引用这些版本。

过敏 `UNKNOWN`、`NO`、`YES` 分别保存；空列表表示尚未记录。主人观察与兽医诊断是不同来源标签，本批不生成诊断、商品适配结论或 AI 输出。

## 使用与后续范围

本地启动沿用根 README 和 M2.4 工程说明。显式开启的 LOCAL DEMO 管理员获得宠物分类维护权限；生产环境不自动授予该权限。管理员进入“宠物分类”维护词典和有来源的年龄规则，消费者登录后进入“宠物”添加档案。

软删除不是隐私删除/匿名化完成；隐私删除策略按后续准入阶段落地。手机 Keychain/Keystore、iOS 签名和正式渠道接入仍沿用 M2 报告的后续范围。M3.2 标准商品与审核、M3.3 Offer、M3.4 确定性适配与搜索业务尚未开始；本批不实现购物车、支付或 AI。
