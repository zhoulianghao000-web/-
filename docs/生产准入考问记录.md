# Pawday 生产准入考问记录

2026-10-11。GrillMe 模拟试点范围访谈已收敛，2026-10-11 用户已要求合并实施计划并开始下一步，整体范围已确认。记录用户已确认的业务方向及生产待决策问题，不代表生产准入、发布审批或新的阶段验收。仓库基线为 M6.5；14 项生产门禁仍为 PENDING。各轮内容为历史记录，当前范围以第五轮及汇总草案为准。

## 第一轮已确认

- 经营模式：混合经营，同时有自营和入驻商家。与实施计划“自营作为特殊商户共享交易系统”一致。
- 主体未明确期间继续内部测试和工程验证；主体明确后，以同一套主体资料规划正式渠道开户。用户尚未提供具体主体、办理负责人或时间。
- 试点地域：重庆；规模方向为少量可直接协调的商家和受邀用户，具体数量尚未确认。
- 允许 Android 先行。这是首发分期方向，iOS 的后续范围和时间尚未确定；当前要求 Android/iOS 签名证据的生产门禁未作调整。
- 明确一名业务审批负责人，由用户组织数据清单、规则草案和适当专业审核。负责人身份、具体权限和审批流程尚未确认。

## 第二轮答复

- 首轮为模拟试点，验证使用体验；真实交易另设准入条件和审批，受邀身份不构成收费许可。
- 用户不承诺无条件兜底。若设置有限赔付，必须先确定资金来源、单笔及累计上限、审批、追偿和经审核的对外规则。尚不能据此判断已选择有限赔付，亦未确认任何额度或资金。
- 自营供应链尚未准备；首轮只验证自营模拟流程。用户表示真实商品先由已准备好的入驻商家提供，其含义是资料展示还是实际交易/发货，需澄清，不能推定首轮获准真实交易。
- 按用户答复理解，初期由用户本人承担业务审批，范围包括首发与商家准入、退款赔付运营规则、经审核的隐私保留注销业务版本，以及开启真实交易试点。答复部分复述了问题原文，后续允许用户纠正此理解；未配置真实员工权限或赋予实际发布授权。
- 首批商家、门店、受邀用户数量和品类仍未提供。

## 第三轮已确认

- 入驻商家提供经授权的实际商品资料。首轮展示资料，订单、支付、退款和发货全部模拟；线下付款和真实发货不能借模拟支付名义纳入首轮。
- 暂不作先行赔付承诺，待资金、规则及专业审核后再决定。尚未设立有限赔付机制、赔付额度或资金。
- 讨论基线：2 家商家、2 个门店、20 名受邀用户、20–50 个商品规格。属于试点规划规模，不能当作已落实商家/授权资料或已验收容量。
- 首轮使用测试账号、虚构地址、样例宠物和预设定位；短信及外部 AI 调用也模拟。尚未证明已有完整、可交付的试点隔离配置。

## 第四轮答复

- 仅指定测试账号可进入，不开放公众注册。这是待实现及验收的准入要求，不表示已有白名单功能。
- 用户允许测试阶段使用图片来源、配料资料或展示授权不可追溯的商品资料；这是对第三轮“经授权实际商品资料”的测试例外，不能写成已经核验授权。例外资料的标识、传播/导出范围和适配结论处理仍需确认。
- 首轮任务：消费者查找商品、宠物适配、购物车、模拟下单及售后；指定人员处理商家操作、管理员审核和审计；工程验证重复操作、权限隔离、异常恢复及外部调用隔离。
- 出现越权、真实扣费或发送、真实资料泄漏时立即暂停；阻塞问题修复并复测后，确认试点结论。按前轮上下文，业务结论由用户作为负责人确认，工程侧提供复测证据。
- 每轮独立测试数据基线；保留脱敏报告及必要反馈；模拟业务数据仅在专用环境内按约定重建。经授权商品资料单独管理，未核验例外资料不能据此获得授权状态或保留依据。反馈提示不提交真实手机号、地址和私人截图。

## 仓库只读核对结果

- 本地支付退款、结算模拟及生产启动拒绝已有基础；尚无完整的重庆受邀试点配置。
- 未发现邀请白名单；现有消费者 OTP 登录可创建账号，尚不满足指定账号准入。
- 本地 SMS 可写测试文件；AI 在 CI 使用 loopback fixture。空密钥或普通 local profile 不能独立证明所有外部副作用隔离。
- Flutter 附近功能默认使用设备定位，导航会打开外部高德；与首轮预设定位、外部调用隔离要求有需落实的差距。
- 现有支付页面有开发模拟提示，尚未发现贯穿三端的统一试点标识。
- 已有真实前后端 CI 验证工程 fixture，但未证明重庆试点 seed、白名单和上述隔离要求已交付。

## 第五轮已确认及汇总理解

- 未核验资料仅向测试账号展示，标记“未核验，仅供测试”，不直接转为生产发布资料。缺少可信配料或过敏原依据时，宠物适配结果为信息不足；正向/冲突适配测试使用明确标记的合成测试商品。
- 定位允许、拒绝、关闭及导航失败使用预设场景；真实设备定位和高德交接留待后续专项验收。首轮按固定重庆测试坐标、导航仅预览且不唤起外部应用的边界整理草案，待整体确认。
- 用户答复“更便于观察使用过程、收集问题和及时暂停”，按上一轮 A 选项理解为集中现场测试。场地、Android 设备、网络和测试时间尚未落实，不虚构已具备。
- 初期审批负责人按用户本人理解；通过整体确认核实该解释及集中现场方式。
- 工程实现细节由工程侧提出并验证：测试账号发放、隔离网络、模拟供应商和三端标识等尚未实施。20 人现场体验也尚未执行。
