## 监控边界

`PAWDAY_METRICS_SCRAPE_TOKEN` 默认空，禁用机器采集身份；配置后要求 43–128 位 URL-safe 字符，通过服务端 Secret 注入。此身份只接受精确的 `/actuator/prometheus`，没有用户/商家/管理员身份，不能读取通用 metrics、业务、审计或执行重放。原管理员 outbox.read 权限保留。管理接口应位于私网并由 TLS 代理保护，不能将测试 HTTP 编排当作正式部署模板。

新增固定维度的数据库可用性、支付 UNKNOWN 数量/年龄、退款待处理/过期租约/最老年龄、结算重试和已结算扣账差异指标。既有 Outbox/inbox/SMS DEAD、积压和 AI 租约指标沿用；不将用户、订单、商家 ID、原始问题或供应商正文加入标签。结算扣账差异指标只覆盖 debit-match 不变量，完整七项仍通过现有结算对账接口执行。

`deployment/operations` 有 12 项 Prometheus 告警、规则时间序列测试、Alertmanager webhook 的发送/恢复配置。机器凭证从只读文件加载；`compose.operations.yaml` 是带 TEST_ONLY 数据库和本地接收器的工程编排。生产 receiver、TLS、人员值班、去重升级和阈值预算仍需单独配置、批准并实测。告警只通知，不自动重放、退款或更改账本。

门禁必须实际经历 PostgreSQL 事实 → 受控端点 → Prometheus → Alertmanager → 本地鉴权 HTTP receiver。接收器前两次返回 503，要求真实重试后送达，并验证问题解除后的 resolved。另停/启仅本批 PostgreSQL，验证不可用及恢复通知；不是手工构造 Alertmanager alert 冒充指标链路。

## 数据加密版本与轮换

现有 `PAWDAY_AUTH_SECRET` 保持不变，继续负责历史 AES 密文及 OTP HMAC。此批没有实现 HMAC/身份主密钥轮换，不得在旧数据库上运行重新生成来替代轮换。

新配置 `PAWDAY_DATA_ACTIVE_KEY_ID` 默认 `legacy`，`PAWDAY_DATA_KEYS` 默认空。启用新数据密钥时格式为 `id:base64-32-byte-key,id2:base64-32-byte-key`；值只能由 Secret 系统注入。key ID 为小写标识（最长32位），禁止重复及保留名 legacy。新 key 必须与 auth key 不同；同一 ID 的值不可替换。新写入使用 `pd1:<key_id>:<AES-GCM密文>`，key ID 也进入 AAD，不能换标签解密；随机 nonce。旧无版本密文继续按 auth key 读取。活动版本改变只影响新写入，不自动修改历史记录。

轮换顺序：先给所有实例配置旧+新两个版本，保留旧 active；验证兼容后把 active 切新；回退 active 时仍保留两个读版本。缺失历史版本会被拒绝；启动时检查四个持久化加密字段的版本引用，不打印密文或 Secret。当前 DB 无引用不代表旧备份不需要该 key，退休前还须盘点备份保留窗口、灾备副本和在途实例。

历史批量重加密、Secret 管理器/审批/审计接入、备份密钥托管、真正 key 退休和 auth/HMAC 轮换仍待后续；本批不提供无审批在线 rekey 端点，不伪称现存密文已迁移。真实 PG 和恢复门禁验证 legacy/old/new 三类密文、轮换后的 TOTP、旧 key 丢失拒绝与 HMAC 保持不变。

## 隔离逻辑恢复

`operations_bundle.py` 封装离线数据库 custom dump + 媒体对象的 SHA256 清单。源必须先停止写入；媒体只接受受控对象 key，拒绝软链/硬链/路径越界/额外文件、错提交、未来时间、hash/size 错误、未知字段和覆盖已有包。清单只保存 key 的 `secrets://` 引用，绝不把 key 值放入数据库或媒体备份。SHA256 证明完整性，不证明备份来源的真实性；仍需受控存储、签名/审批和外部密钥备份策略。

`operations-engineering-gate.py --test-only --commit <实现SHA>` 拒绝脏工作区，代码树必须对应提交；只接受标签匹配的固定工程源数据库，不接受任意 DB 地址/容器/外部 webhook。停止它自身启动的应用后，在合成数据上执行真实 pg_dump。恢复目标是随机新建的 PostgreSQL，单独 internal 网络、无端口映射、无应用/worker/MQ/云端凭证；空库检查后使用 pg_restore `--single-transaction --exit-on-error --no-owner --no-privileges`。不使用 --clean、不覆盖已有数据库。

恢复前验证整个包，损坏包必须在建目标前拒绝；恢复后逐表逐行 hash 比较、核对源库未改变、媒体字节与 media_asset 引用一致、三版本密文能解密、缺 key 拒绝、inbox 唯一约束和 append-only ledger 仍有效。只清理本次随机生成且标签精确匹配的目标及网络，现有开发/其他项目服务不参与清理。报告不包含行内容、凭证或媒体本体。

此处是停止写入的合成逻辑恢复演练；未覆盖 PostgreSQL WAL/PITR、线上持续备份、正式对象存储、密钥托管恢复、隐私删除墓碑重放、渠道 UNKNOWN 查询和搜索重建。不能从工程秒数推导或宣称正式 RPO/RTO 达标。恢复生产副本还须先隔离外部副作用，核对渠道事实和删除/撤权状态后受控解除隔离，不能直接启动消费者重放。
