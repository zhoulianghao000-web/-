# M5.3 人工客服与消息

基线为 PR #15 合并后的主分支 `43e0f589e922fddd2f84cba9041a19cefcc04769`。只增加 V018；V001–V017 不改写。本阶段是否通过，以验收报告中的真实 CI 和包验证为准。

## 私有会话与权限

消费者发起 PLATFORM 或具体门店 MERCHANT 会话，每位消费者与每个平台/门店保留一个会话，可关闭和重新打开。商家不提供任意用户营销发信接口。游客先登录，保留 `returnTo`；订单/商品页提供上下文入口。

员工的 `support.read` 允许查看当前平台或当前 merchant/store 的队列元数据，不授予未分配会话的消息读取权限。消费者及当前分配客服为活动参与方，只有参与方可读取消息、卡片与图片。客服回复另需 `support.reply`。领取、重新分配与转接需 `support.assign`、If-Match、幂等键、一次性二次验证凭证和同事务审计；目标员工必须当前有效、具备读/回复权限且属于相同平台或商家门店。转接后旧客服失去历史及私有附件访问权限。平台客服不能绕过边界查看商家会话。

订单卡片保存子订单引用，打开时按消费者所有权或员工订单权限重新核验。子订单按商家聚合，因此门店授权依据订单项；卡片不授予其他门店权限。商品卡片读取当前商品与在售报价；下架或退休后返回不可用，不能按历史卡片假定仍在售。聊天正文以纯文本渲染。

## 保存、读取与交付

消息不可覆盖，支持文字、图片、商品卡片、订单卡片。会话行锁分配严格递增序号；发送命令、消息行、媒体引用与 Outbox 同一个 PostgreSQL transaction 提交。重复命令返回同一条消息，换正文复用键返回冲突。正文、电话号码与图片字节不进入 Outbox。

前端用持久化序号增量读取并定时更新，接口提供最长 20 秒的有界等待，断线可从最后序号继续。等待期间不持有事务或数据库连接，并逐次重查当前会话、角色和参与者授权。已读游标只能前进且不得超过现存消息；只统计对方消息为未读。

RabbitMQ quorum queue `pawday.support.notifications` 在 broker confirm 后完成 Outbox 发布；`support-notifications-v1` inbox 在 PostgreSQL 去重，提交业务结果后 ack。单条交付标记保留事件身份，会话交付游标只跨越连续已完成的消息，不会因乱序误报缺失消息已交付。有限指数重试、DEAD/DLQ、管理员受 RBAC/reverify/audit 控制的重放沿用 M2.2。MQ 不可用时消息仍可保存和查询；外部传输/通知待恢复后补齐。

聊天图片使用已有 CHAT 受控上传凭证，仅 PNG/JPEG、最大 5 MiB、每条最多 4 个资源。文件类型/大小/有效期与实际内容在服务端验证。数据库只保存引用，引用后的媒体不可被删除；读取为鉴权接口、`private, no-store` 和 `nosniff`，不发布公共对象 URL。会话、门店或身份变化时前端清除私有内容、待发送附件和凭证，迟到响应不能填回旧会话。

## 消息中心与边界

冻结七类提醒 taxonomy：ORDER、AFTERSALE、PRICE_DROP、RESTOCK、FOOD_REMINDER、ACTIVITY、SUPPORT。每类独立设置，默认开启；设置与 OS 推送权限分开。消息记录保留，`notify_enabled` 冻结生成时的业务提醒偏好，不声称已接入生产系统推送。本批连接真实订单/履约、售后与人工客服事件；其他类型的生产者随对应业务阶段接入，不能凭空生成活动、降价或吃粮事件。

消息中心按当前身份读取、分页与单条已读；跳转目标再次验证所有权。前端使用同一个 OpenAPI 3.1 `pawday-m5.3.yaml` 生成 TS/Dart DTO，CI 检查生成一致性、端点采样覆盖和私有二进制样本。

V1 只使用人工客服，保留 `SupportAssistant` 接口供未来低风险 FAQ/状态解释转人工，不实现 AI 自主处理。生产推送、内容风控供应商、保留/删除政策与容量压测归 M6 准入；附近/高德为 M5.4，DeepSeek 解释层为 M5.5。
